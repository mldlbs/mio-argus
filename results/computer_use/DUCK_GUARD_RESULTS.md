# DUCK 执行适配器（MioArgus 第二执行环境）结果

> 日期：2026-11-11　状态：**门禁已通过，L1/L2 开放，L3 禁止**
> 协议：`docs/DUCK_EXEC_PROTOCOL.md`

## 1. 目标与结论

把 Telegram 小程序 DUCK × MY × DUCK 作为**非结构化、像素化、有副作用**的执行环境，验证 MioArgus 能否在“证据不足时可靠拒绝执行”。

结论：**可以**，但前提是执行前必须有页面断言、目标核对、风险授权与后置断言四层，而不是“定位到坐标就点”。

## 2. 架构

```
视觉枚举（槽位 / 蛋格）
  → 目标核对（类型 + 等级，两格互验）
  → 页面断言（多锚点 + 5 次重试）
  → 风险授权（L0 自由 / L1 导航 / L2 喂食合并 / L3 默认拒绝 / L4 永久禁止）
  → 动作（点击 / 拖拽）
  → 后置断言（等级提升 或 队列消耗）
  → 事件流（带 tier/task/reason/证据）
```

全部动作经 `authorize()`；页面未确认时唯一允许的动作是 `go_home()`（点「蛋」标签）。

### 5.1 调度语义：喂食中断不得自动切页（2026-11-12）

原先 `one_cycle` 对到点的层级**无条件串行**：`routine(collect→feed)` 跑完不管结果都接着 `upgrade(merge)`，
而 merge 第一步是 `goto("egg")`，于是出现「鸭子没喂满就跳到蛋页」。

现在把 `feed` 的结束原因显式记录并据此决定调度：

| `stop_reason` | 含义 | 后续动作 |
|---|---|---|
| `cap` | 单价达到 200 | 正常进入合并 |
| `no-feedable` | 有槽位但都不可喂（已满/出售/质押/繁殖中） | 正常进入合并 |
| `max_rounds` | 单轮只数上限（默认 10 只） | 正常进入合并，余下留到下一轮 |
| `vision-miss` | **整排槽位识别为空**，属观测失败 | **本轮不切页**，`defer_upgrade`，合并推迟 |

配套两点：
1. `find_feedable` 在整排视觉为空时先重载鸭子页重试一次，仍为空才判 `vision-miss`；
2. `max_rounds` 从硬编码 6 提到可配置 `feed_rounds=10`。

关键区分：`no-feedable` 是**游戏状态**，`vision-miss` 是**观测失败**。只有前者允许改变页面。

### 5.2 单只到顶不等于整轮结束（2026-11-12）

`do_feed` 返回 `stopped=cap` 时，原先直接 `break` 退出整个喂食循环，结果是
**第一只到 200 就收工，其余鸭子本轮完全没喂**。

现在改为「这只到顶 → 记入 `capped` 跳过集 → 继续找下一只」：

```
if fed["stopped"] == "cap":
    capped.add(g.last_slot)          # 不再重复选中同一只
    price = find_feedable(g, skip=capped)
    if price is None: 结束
    else: continue                   # 换下一只继续喂
```

配套：`find_feedable` 增加 `skip` 参数并记录命中槽位 `g.last_slot`。
`stop_reason` 因此收敛为三种真实结局：`no-feedable` / `vision-miss` / `max_rounds`。

### 5.3 鸭子页结构更正与单轮实测（2026-11-13）

**结构误判**（此前所有“点开非鸭子页 / 点开锁槽”的根源）：

| 原假设 | 实际 |
|---|---|
| 底栏上方那排小图标是鸭子槽位 | 是**收藏/奖励进度条**（鸭群、升级、皇冠、灰点、宝石、挂锁） |
| 点图标可选中鸭子 | 点它只会打开收藏页或 `BUY A SLOT` |
| —— | 切换鸭子只能**横向快拖** `(0.75,0.47) → (0.25,0.47)` |

因此 `find_feedable` / `find_ready_to_breed` 全部改为**轮播遍历 + 像素差判定是否移动**，
不再点击图标行。

**单价读取**：气泡是 `点击喂食 🌽96`，整条 OCR 稳定输出 `点击喂食%`；
改为只裁玉米右侧数字区（`PRICE_BOX`）并 4x 放大，`96/204/210` 全部读对。

**单轮实测（2026-11-13 07:51）**：

| 指标 | 值 |
|---|---|
| 喂满到 200 的鸭子 | 3 只（119 / 130 / 103 次） |
| 累计喂食 | **352 次** |
| 停止原因 | `cap` → 换下一只 → 最后 7 只新鸭子无槽位 |
| 星星 | 30★（未变化） |

用户选择：不买星星、不解锁、不卖鸭子，只靠任务/成就攒星星。

### 5.4 爱心蛋收集（2026-11-13）

机制（用户确认）：爱心蛋攒在每只鸭子身上，**点鸭子卡片本体**即收集；
已收过时再点会提示「暂无爱心蛋。稍后回来即可获得爱心蛋。」

原实现点的是一列写死的左侧图标（`LOVE_ICONS`），那些位置现在是
`DUCKER PASS` / `DAILY PASS` 图标，所以 `love_eggs` 长期为 0。

现在改为「轮播遍历 + 每只点一下」：

```
click(0.50, 0.47)     # 卡片本体；喂食气泡在 (0.50, 0.62)，不会误触
if 面板出现「领取/收取」: do_claim()
carousel_next()
```

实测单次可点 **7–9 只**鸭子。

顺带修掉一个真问题：点鸭子有时弹「每日奖励」面板，`领取` 按钮在 **y≈0.84**，
而 `do_claim` 只扫 0.42–0.92 的窄带正好漏掉 → 改为整块卡片 (0.03,0.10,0.94,0.86)，
并优先点最靠下的按钮。当日实际领到：每日奖励 2500 + 喂鸭大赛排名奖。

## 6. 已知限制

1. **empty / other 两类不可达**（槽位行不存在空槽与装饰元素），按 A1 收敛为 `{duck, padlock}`；两者保留为安全类，出现时输出 `unknown`。
2. **图标素材固定**，匹配分数集中在 0.96–0.98；换皮/换分辨率未验证。
3. **视觉聚类阈值 0.22 会产生假配对**，靠“两格等级互验 + 后置断言”兜底，代价是 2 次读图。
4. **合并后蛋板立即补货**，不能用“目标等级 +1”作为唯一证据，已改为“等级提升 或 队列消耗”。
5. **定时器文案会变**（如 `下一颗蛋及后续` → `自动合并`），页面规则必须多锚点容错，且锚点失效必须在事件流里可见。

## 7. 与 Bigemap 的差异（为什么不能复用同一套）

| | Bigemap / QGIS | DUCK |
|---|---|---|
| 控件树 | 有 UIA，可按名字定位 | 只有一个 Chromium 渲染窗口 |
| 布局 | 固定面板 | 轮播自动居中、蛋板合并后重排 |
| 反馈 | 可查控件状态 | 只能 OCR，且面板有 1 帧延迟 |
| 副作用 | 点错通常无反应 | 点错可能购买、开活动页、弹订阅 |
| 结论 | 精确执行即可 | **必须先证明“看到的是什么”再决定“动不动手”** |
