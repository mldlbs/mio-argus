# 方向 B 基准：候选召回与语义排序（阶段 3 前置诊断）

> 复现：
> ```
> python experiments/computer_use/candidate_bench.py --stage b1
> python experiments/computer_use/candidate_bench.py --stage b2 --ranker lexical
> set HF_HUB_OFFLINE=1
> python experiments/computer_use/candidate_bench.py --stage b2 --ranker qwen
> ```
> 数据：`results/computer_use/candidate_bench.json`、`candidate_b2_lexical.json`、`candidate_b2_qwen.json`

---

## 1. 结论

> **B 方向的瓶颈不在排序，在候选召回。**
> 目标控件出现在候选集里的比例只有 **34.7%（75/216）**。
> 在可召回的 75 条上，最好的排序器（词面 IDF）Top-1 **40.0%**。
> 端到端 = 34.7% × 40.0% = **13.9%**，远低于纯视觉 A3u 的 **62.5%**。
> 因此**现在训练排序模型没有意义**——先修候选生成。

## 2. B1：候选召回

| 项 | 值 |
|---|---|
| 样本 | 216（同冻结集） |
| 候选来源 | 录制时的 affordance 列表 |
| 叶子化 | 去掉面积 > 25% 屏幕的容器，按矩形去重 |
| 候选中位数 | **58**（p90 = 59） |
| **正确控件在候选集中** | **75 / 216 = 34.7%** |

候选中位数 58、p90 59 —— 说明录制时 `struct[:60]` 的截断仍在生效，
而且列表里混着大量非目标控件。

**这不是排序问题**：65.3% 的样本，正确答案根本不在候选里，任何排序器都无能为力。

## 3. B2：候选排序（仅 75 条可召回样本）

| 排序器 | Top-1 | Top-3 | MRR |
|---|---|---|---|
| **词面 IDF（零模型基线）** | **40.0%** | 44.0% | 0.449 |
| Qwen2.5-1.5B-Instruct（词面 top-10 短名单内选） | 20.0% | 25.3% | 0.260 |

- 本地 1.5B 模型在这个任务上**明显不如词面匹配**（与之前 55 候选实验的结论一致）。
- 词面基线 40% 已经是"可召回条件下的上限参考"，换更强的排序模型前，必须先解决召回。

## 4. 与方向 A 的对照

| 路线 | 端到端 Top-1 | 成本 |
|---|---|---|
| A3u（纯视觉，一级放大） | **62.5%** | 3.5 s/条 |
| 候选路线（召回 34.7% × 排序 40%） | 13.9% | 排序 ~0.2 s + 候选生成开销 |

当前视觉路线明显更强。候选路线的价值在于**确定性**与**可解释性**，
但要先修数据，不能靠训练排序器硬补。

## 5. 下一步（按优先级）

1. **重新采集候选**：去掉 `struct[:60]` 截断、只保留叶子控件、带上 Qt 的 action / accessibleName。
   这是数据问题，不是模型问题，也是 B 方向唯一能让召回从 35% 往上走的前提。
2. 召回修好后重跑 B1/B2，再看排序是否成为新瓶颈（词面 40% 是要超越的线）。
3. **仍不训练**：在召回 < 80% 之前，训练排序模型无法体现价值。

## 6. 局限

- 候选来自历史录制，无法回溯补采；重采需要重跑 QGIS 链路（约 40 分钟）。
- 75 条可召回样本的排序指标方差较大（±6 个点量级）。
- Qwen 短名单只取词面 top-10，未测全量候选；但全量 58 个候选对 1.5B 更不利。
