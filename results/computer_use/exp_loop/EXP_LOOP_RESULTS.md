# 经验闭环（exp_loop）第一轮结果

> 日期：2026-11-14　状态：**闭环跑通，3/5 条验收标准达成，2 条部分达成**

## 1. 这一轮要回答的问题

用户指出的根本问题：

> DUCK 目前表现出来的是「工程师不断修正系统」，而不是「系统自己从经验中学习」。
> 应该由系统从原始失败记录中自主生成经验，并在未参与生成的样本上验证。

所以本轮不做模型训练、不做 Agent，只用**已经发生过的那三类错误**做回放验证：

| 机制 | 原始现象 |
|---|---|
| `gap_click` | 点在两颗图标之间的缝隙，界面没反应，却把旧卡片当成结果 |
| `sentence_click` | 点在长句说明文字上（不是按钮），点了没反应 |
| `empty_ocr` | 仅识别通道返回空串，链路把「识别失败」当成「没有内容」 |

以及两类负样本：`good_click`（正常选中）与 `blank_ocr`（画面本身空白）。

## 2. 协议（关键在"系统不许偷看答案"）

```
原始观测（episode）  →  归因（只看 episode）  →  候选规则  →  独立验证  →  晋级/淘汰
        ↑                                                          ↓
   采集只记录：动作 / 动作前后画面+文本 / 期望的可观测变化            只有 active 进生产
   不含任何"原因"字段；标签单独存 labels.jsonl，归因不读
```

- **切分**：`crc32(episode_id) % 2` 决定 train/val，同一 episode 永远落在同一半区。
- **阈值选择**：只在 train 半区选（网格搜索 `recall - FPR`）。
- **晋级门槛**：val 半区 `recall ≥ 0.90` 且 `FPR ≤ 0.05`，且两侧样本量 ≥ 2/3。
- **适用范围**：每条规则只在它关心的动作类型上评分（否则 OCR 样本会被算进点击规则的 recall 分母）。

## 3. 数据

```
24 个 episode：positive 9 / negative 15
  gap_click 4 | sentence_click 1 | empty_ocr 4
  good_click 9 | blank_ocr 6
```

## 4. 结果（val 半区，未参与阈值选择）

| 规则 | 假设 | val recall | val FPR | 判定 |
|---|---|---|---|---|
| `R1_assert_effect` | 动作后必须观测到画面/状态变化 | **1.0** (3/3) | **0.0** (0/4) | **active** |
| `R3_empty_is_not_absent` | 空串 ≠ 内容为空，必须回退第二通道 | **1.0** (3/3) | **0.0** (0/3) | **active** |
| `R5_hit_icon_center` | 落点必须在图标中心容差内 | **1.0** (3/3) | **0.0** (0/4) | **active** |
| `R2_refetch_after_action` | 文本未变 → 必须重新取证 | 0.0 (0/3) | 0.5 (2/4) | **淘汰** |
| `R4_labels_only` | 可点目标必须是短标签 | — (val 无正样本) | — | **拒绝晋级** |

**R2 被淘汰是这一轮最有价值的结果**：它看起来是最"显然"的规则
（文本没变就重新取证），但在数据上 FPR=0.5——因为**相邻两只鸭子可能完全同款**
（同稀有度/等级/单价/状态），文本本来就不会变。这条规则如果凭直觉写进生产，
会把大量正常操作误判成失败。

**R4 拒绝晋级**：只有 1 个正样本且落在 train，val 半区没有样本，
数据上根本无法验证，因此不允许进生产（哪怕 train 上 recall=1.0）。

## 5. 生产接入（经验不直接改行为）

`duck_guard.py` 启动时读取 `results/computer_use/exp_loop/rules.json`：

```
经验规则已生效：R1_assert_effect(R=1.0,FPR=0.0)；R3_empty_is_not_absent(R=1.0,FPR=0.0)；R5_hit_icon_center(R=1.0,FPR=0.0)
```

闸门有两层：

1. **status 必须是 active**（proposed 一律不生效）；
2. **必须找得到执行钩子**（`EXP_HOOKS` 映射到真实函数名，找不到就打"缺少执行钩子，未生效"）。

这样"模型认为自己理解了"不会变成系统知识——它必须同时满足「经验库标 active」+「代码里有可验证的执行点」。

## 6. 对照用户给的 5 条验收标准

| # | 标准 | 结论 | 证据 / 缺口 |
|---|---|---|---|
| 1 | 不依赖人工提供故障原因 | **部分** | episode 里没有任何原因字段，归因也不读标签；但**候选 detector 是先验写死的**，人类仍提供了"看哪些量" |
| 2 | 能从原始观测提出正确失败假设 | **是（部分机制）** | 3 条假设在独立样本上 recall=1.0；1 条被数据否掉；1 条样本不足 |
| 3 | 能生成机器可执行的经验规则 | **是** | 规则含 version/status/condition/hook/metrics/invalidate_if，且映射到真实钩子 |
| 4 | 独立测试显著降低同类失败 | **部分** | 验证器层面成立（val recall 1.0 / FPR 0）；**生产层面尚未做 A/B**（规则其实是已修好的代码，缺"开/关规则"的对照运行） |
| 5 | 错误经验不能污染生产 | **是** | R2 被淘汰、R4 拒绝晋级；active 还需钩子存在性检查 |

## 7. 诚实结论

这一轮做到的是：**把"人改代码"变成了"候选假设 → 数据裁决 → 带指标晋级"的流水线**，
并且真的用数据否掉了一条直觉上很合理的规则。

还没做到的是：**系统自己发明候选量**（现在的 5 个 detector 是人写的先验），
以及**生产侧 A/B**（证明失败率真的下降，而不只是验证集上的数字）。

所以更准确的定位是：**从"人改代码"退到"人给候选、数据决定"**，还没到"系统自学"。

## 8. 下一轮最小验证

1. **detector 合成**：把"看哪个区域 / 什么阈值 / 什么文本特征"也放进搜索空间，
   用同一套 train/val 协议筛选 —— 这一步才真正减少人类先验。
2. **生产 A/B**：同一套任务，规则开/关各跑 N 轮，比较「静默失败率」（动作后读数与真实状态不一致的比例）。
3. **经验过期**：规则带 `expires` 与回归窗口，FPR 回升自动 retire。

## 9. 产物

```
results/computer_use/exp_loop/
  episodes.jsonl      原始观测（无结论字段）
  labels.jsonl        标签（仅验证器使用）
  frames/*.png        动作前后帧
  hypotheses.json     归因输出 + 选中的阈值
  rules.json          经验库（含 metrics / gate / status）
```

复现：

```powershell

python experiments/computer_use/exp_loop/run_loop.py             # 用已有 episode 重跑归因+验证
```

# 第二轮：自动合成 Detector（2026-11-14 晚）

## 1. 这轮改了什么

上一轮是「人写 detector、系统选阈值」。这轮把**判别关系本身**也交给搜索：

```
原始 episode → 自动提特征（像素差分/能量/文本/几何，30+ 维）
            → 自动生成候选（单特征阈值 380 条，阈值取 train 分位点）
            → 自动组合（双子句合取，跨特征族）
            → train 定阈值 / val 选规则 / **test 独立裁决**
```

人类只提供**特征族**（"可以看像素差分、能量、文本、几何"），
不再指定"该看哪一格、阈值多少、怎么组合"。

## 2. 数据（三个批次累积）

```
207 个 episode（positive 103 / negative 104）
机制：缝隙点击 / 长句说明 / 识别空串 / 点错导航 / 正常点击 / 空白区域 / 右侧区域
切分（crc32%3）：train 64 / val 78 / test 65
```

标签由**独立判定器**给出，不由采集方式决定：

- 点击类：必须「仍在鸭子页」且「选中格落在被点位置 ±0.022」才算成功；
- 识别类：仅识别通道返回空、而整页识别能读出文字，才算识别失败。

## 3. 人类先验规则（对照基线）

| 规则 | status | val tp/n_pos | val fp/n_neg |
|---|---|---|---|
| `R1_assert_effect` | active | 15/45 | 0/28 |
| `R2_refetch_after_action` | active | 13/45 | 1/28 |
| `R3_empty_is_not_absent` | active | 7/7 | 0/25 |
| `R4_labels_only` | proposed | 2/2 | 0/0 |
| `R5_hit_icon_center` | active | 14/45 | 0/28 |

人类规则在 test 上覆盖 18/38 个正样本，
**剩余 20 个是人类没抓到的**（主要是「点错导航」类）。

## 4. 自动发现（只在残差上计分）

| 自动规则 | 判别式 | val | test | 结果 |
|---|---|---|---|---|
| `A_G_x_>e_546` | `G_x >= 0.546` | 20/35 (fp=0) | 22/38 (fp=0) | active |
| `A_T_len_b_>e_169000` | `T_len_b >= 169` | 9/35 (fp=0) | 7/38 (fp=0) | active |

候选 380 条 → val 选中 2 条 → test 全部通过（fp=0）。

## 5. 自主发现率

```
自主发现率 = 自动发现且通过 test、并覆盖人类漏掉正样本的新规则数
           / (该数 + 人类规则中在 test 上成立的条数)
         = 2 / (2 + 1) = 0.667
```

自动新发现：`['A_G_x_>e_546', 'A_T_len_b_>e_169000']`；人类在 test 上成立：`['empty_recognition']`。

## 6. 但这一轮最重要的发现是：**系统自己提出的规则是可疑的**

`G_x >= 0.546`（点击位置在槽位带右半侧 = 高风险）在 test 上 tp=22、fp=0，
看起来非常漂亮。但它是**采集几何的产物**：当前游戏状态下挂锁都在右侧，
而"右侧合法点击"这种反例在数据里根本不存在。

我们尝试专门采一批右侧点击来证伪它——结果那批点击**全部落在挂锁上**
（同样被标成正样本），反而加强了这条假规则。

这正是用户提醒的那个陷阱：**没有真正的独立对照，漂亮的 fp=0 只是采样偏差。**
因此这条规则**不接入生产**，并标记为"需要反例场景（有鸭子位于右侧时的布局）才能验证"。

同理 `T_len_b >= 169`（文本很长 = 任务页）只是"页面身份"的代理量，
不是失败机制；它能命中句子点击，但也会命中任何正常的长文本页面操作。

## 7. 结论

| 问题 | 结论 |
|---|---|
| 系统能否自动提出判别关系 | **能**（380 候选 → 2 条过 test） |
| 自动提出的规则是否可信 | **本轮不可信**（位置规则被采集几何污染，文本长度规则是页面代理量） |
| 自主发现率 | 机械计算 0.667，**扣除混杂后实质为 0** |
| 这一步真正证明了什么 | 闭环能把"候选生成"也自动化；但**没有独立反例场景，验证会自我欺骗** |

## 8. 下一步（比继续加特征更重要）

1. **反例场景构造**：必须能在"鸭子位于右侧"的布局下采样，否则位置类规则永远无法证伪；
2. **页面身份特征隔离**：把"这是哪一页"从判别特征里剔除，否则规则会退化成页面识别；
3. **标签噪声治理**：同一批 good_click 在不同批次里既有 positive 也有 negative，
   说明判定器有时序抖动，需要多次采样取多数；
4. 生产 A/B 仍未做。

# 第三轮：主动证伪 + 三个学习指标（2026-11-14 深夜）

## 1. 这轮补的是"怀疑自己"的能力

上一轮系统提出了两条规则并通过了独立 test。这轮不接入生产，
而是让系统**自己去证伪它们**：

```
规则 → 抽隐含前提（位置？页面身份？几何？文本变化？）
     → 覆盖分析（命中区间里有没有成功样本）
     → 提反例场景规格（针对薄弱环节，不是随机补样本）
     → 真实界面构造（构造不出就报"不可构造"，绝不伪造）
     → 裁决：refuted / holds / insufficient
```

## 2. 逐条裁决

| 规则 | 隐含前提 | 裁决 | 依据 |
|---|---|---|---|
| `A_G_x_>e_546` | positional | insufficient | 不可构造：向右无路可走；试过的位置：['0.678=缝隙'] |
| `A_T_len_b_>e_169000` | page_identity | refuted | 反例成立：长文本页面上完成了一次有效动作（子标签切换成功） |

### 关键点 1：`A_T_len_b` 被真实反例推翻

它的隐含前提是「文本长度 ≥169 的页面上的动作都是失败的」。
系统提出反例场景：**在同一类长文本页面上完成一次合法动作**。
执行器真的切到了 `广告` 子标签并验证内容出现——反例成立，规则失效。

### 关键点 2：`A_G_x` 被判"不可构造"，没有被冤枉

位置规则要求"在 x ≥ 0.546 处存在合法可点对象"。
执行器逐个位置尝试并记录证据：可达的位置只有 `0.678=缝隙`，再往右无路可走。

```
裁决：insufficient — 不可构造：向右无路可走；试过的位置：['0.678=缝隙']
```

**这正是用户要求的边界：构造不出来就报不可构造，不许伪造反例。**
上一轮它看起来 22/22 fp=0，其实只是"这一布局下右边没有鸭子"。

## 3. 三个学习指标

| 指标 | 值 | 含义 |
|---|---|---|
| Discovery Rate | **2** | 独立生成并通过独立 test 的**机制**数（按触发向量去重，同机制不同阈值只算 1） |
| Falsification Rate | **1.0** | 实际做了反例尝试的规则里被推翻的比例（1/1） |
| Robust Discovery Rate | **0.0** | 通过反例测试 + 独立 test 后仍成立的机制比例 |

**Robust = 0.0**：两条机制一条被反例推翻、一条无法构造反例（证据不足）。
证据不足**不算稳健**——那是"没被检验"，不是"检验通过"。

高 Falsification Rate（1.0）在这里不是坏消息：
**两条自动生成的规则，一条被证伪、一条被标记为"无法验证"，这比 2 条静悄悄进生产好得多。**

## 4. 对照第七节的验收条件

| # | 条件 | 结论 |
|---|---|---|
| 1 | 不提供人工指定的反例位置 | ✅ 场景由 `scenario_generator` 按前提类型自动提 |
| 2 | 系统自己识别未覆盖条件 | ✅ 覆盖分析报「命中区间内 0 个成功样本」「阈值单侧」 |
| 3 | 系统自己提出反例场景 | ✅ 位置类 → "找同位置的合法对象"；页面类 → "同页面完成合法动作" |
| 4 | 能真实构造至少一种反例布局 | ✅ 长文本页面上的合法动作真实执行并验证 |
| 5 | 自动判定 成立/失效/证据不足 | ✅ 三态判决（refuted / holds / insufficient） |
| 6 | 反例结果自动更新假设状态 | ⚠️ **部分**：写入 `falsification.json`，但尚未回写 `auto_rules.json` 的 status |
| 7 | 可重复、可审计、不依赖人工标注 | ✅ 全流程脚本化，证据落盘（试过的位置、页面跳转、动作结果） |

## 5. 仍然没做到的

1. **状态回写**：证伪结论还没自动把规则置为 retired，需要下一轮补（一行代码的事，但属于流程闭环）。
2. **反例场景仍由前提类型白名单驱动**（positional/page_identity 两种），
   遇到未登记的前提类型只会报"暂无场景规格"，本质上还是人类给了场景模板。
3. **生产 A/B 依旧未做**（P0 里被主动证伪取代）。
