# M3 预注册：颜色捷径的因果检验

> 状态：**预注册 v1.0（2026-11-17）— 未训练、未改代码**
> 依据：`EVIDENCE_GAPS.md` C6（`cls` 饱和疑似颜色捷径）+ §7（E1-L 因无测量窗口暂停）
> 定位：这是一次**单点因果检验**，不是 E1-L 重启，也不是 H2 重做。

---

## 0. 边界（先钉死）

**M3 只回答一个问题**：`cls` 的高命中率有多少依赖"标签专属颜色"。

| 不做 | 理由 |
|---|---|
| 不重启 E1-L（36 次训练） | 测量窗口问题未解决（§7） |
| 不修改 P0/P1 的历史结果或缓存 | 保证可追溯 |
| 不用 M3 结果自动恢复 H2 或 E1-L | 一次消融不足以支撑因果结论 |
| 不把 `reg` 当成"接地能力的正确度量" | 用户已明确：我们要的是**有效测量工具**，不是"能让分数下降的改造" |

## 1. 因果问题与可证伪预测

**问**：把"标签 → 颜色"的对应关系打断（颜色仍多样、但不再指示标签），`cls` 的命中率会掉多少？

**预测（可证伪）**：

- 若 C6 的强版本成立（颜色是唯一线索）→ `cls` 掉到 **≈随机（1/36 ≈ 0.028）**；
- 若颜色只是部分线索 → `cls` 掉到 **0.1–0.5**；
- 若颜色无关紧要 → `cls` **基本不掉（≥0.85）**，则 C6 的强版本被否证。

**关键前提**：本环境的标签身份**只由颜色承载**。因此"掉到随机"同时也意味着
"该消融下任务不可解"——这一点必须在结果里写清楚，**不能解读为"模型不会接地"**。

---

## 2. 消融语义（核心，防止引入分布变化）

| 条件 | 颜色分配 | 说明 |
|---|---|---|
| `by_label`（对照） | `color = PALETTE[LABEL_TO_ID[label] % 64]` | 现状：标签与颜色一一对应 |
| `permuted`（消融） | **每个样本独立随机置换**：从 64 色中不放回抽 `num_slots` 个，按槽位分配 | 颜色**仍然多样且互不相同**（视觉统计不变），但**与标签无关** |

**明令禁止的做法**：

- ❌ 把所有元素涂成同一颜色（改变颜色分布，引入新的难度来源）；
- ❌ 只在测试集改颜色、训练仍用标签色（会把分布外失效误读成捷径依赖）；
- ❌ 复用 `color_by_label=False` 的旧实现——它现在是
  `PALETTE[rng.integers(0, 64)]`（**有放回**，会产生重复颜色），语义不同。

**训练/测试一致性**：两个条件都在**各自的数据生成**里生效（train seed=0 / test seed=999），
生成流程完全相同，只有颜色规则不同。

## 3. 条件与对照（4 格）

| 格 | color_mode | head |
|---|---|---|
| A | by_label | cls |
| B | by_label | reg |
| C | permuted | cls |
| D | permuted | reg |

固定不变：`grid=6`、`fill=0.40`、`jitter=4`、`img=160`、`width=32`、`epochs=25`、
`n_train=4000`、`n_test=1000`、`lr=3e-3`、`batch=64`、rollout 任务数 300、
**3 个训练种子（0/1/2）× 每种子 2 次重复**、rollout 种子规则沿用 `1000 + H*7 + int(rho*100)`（与 width/k 无关）。

**reg 臂的损失函数（v1.1 补充）**：沿用 `p1_horizon.train_single_step` 的**坐标 MSE**（`coord`），
与 P1 保持可比；**不**改成 `p0_h2.train_one(reg_loss="gauss")`。
理由：M3 的 reg 只是"消融是否同时打死 reg"的对照，两个颜色条件共用同一损失即可；
若换成 gauss，reg 会与 P1 的既有数字不可比，反而引入新的解释负担。
结果文件必须注明"reg 为 coord 实现，与 P0 的 gauss 不可跨文件比较"。

### 3.1 运行矩阵（v1.4：12 → 24 次）

| 条件 | 种子数 | 每种子重复 | 训练次数 |
|---|---|---|---|
| by_label + cls | 3（0/1/2） | 2 | 6 |
| permuted + cls | 3 | 2 | 6 |
| by_label + reg | 3 | 2 | 6 |
| permuted + reg | 3 | 2 | 6 |
| **合计** | | | **24** |

**为什么改成 24 次**：实测同一数据、同一 seed 连续训练三次，`cls` 单步命中为
**0.804 / 0.938 / 0.950（极差 0.146）**——CUDA 侧的运行非确定性不可忽略（见 §10）。
若仍按 12 次（每格 3 个观测）计算 CI，会把运行噪声误当成种子间差异。
**不**改用 CPU、**不**替换 `adaptive_avg_pool2d`：那会改变模型算子，破坏与 P0/P1 的可比性。

### 3.2 重复运行的配对规则（两次重复必须只差"运行"，不差"条件"）

| 项 | 要求 |
|---|---|
| 数据 | **完全相同**的 npz（同一 `env_key` + 同一 n/seed），并记录 `sha256(npz)` |
| **全部随机源** | `random.seed(s)`、`np.random.seed(s)`、`torch.manual_seed(s)`、`torch.cuda.manual_seed_all(s)` 四处**同时**设置 |
| 批顺序 | 现实现无 DataLoader，批顺序由 `torch.randperm(n, device=...)` 决定（受 `torch.manual_seed` 控制）；**若将来引入 DataLoader**，必须 `generator=torch.Generator().manual_seed(s)`、`worker_init_fn=...`、`num_workers=0` |
| 任务样本 | 两种颜色条件使用**同一批任务与目标**（rollout 种子与 width/k 无关；C4 已验证逐位一致） |
| 模型配置 / 预算 | 完全相同（width/epochs/lr/batch） |
| 进程 | **独立启动**（不共享 CUDA 上下文） |
| 记录 | 独立 `run_id = m3-<scheme>-<head>-s<seed>-r<repeat>`；**保存配置指纹 + 数据哈希 + 完整日志** |
| 审计字段 | 每次运行落 `config_fp`（§7 的 JSON 规范化 sha256）、`npz_sha256`、`torch.__version__`、`gpu`、开始/结束时间 |

> 仅设 `torch.manual_seed` 不足以证明所有随机源一致，故上表要求 Python / NumPy / Torch / CUDA 四者齐全。

### 3.3 执行顺序：24 次必须**交错**，不得分块

按 `(cell, seed, repeat)` 轮转执行，例如：

```
A-s0-r1, B-s0-r1, C-s0-r1, D-s0-r1, A-s1-r1, B-s1-r1, ...
```

理由：若先跑完某一格再跑下一格，GPU 温度、驱动负载、后台进程等**时间因素会与实验条件混杂**。
执行顺序写入日志（`run_seq`），便于事后检查是否真的交错。

**训练次数**：4 格 × 3 种子 = **12 次**（不是 36 次，也不并入 E1-L）。

## 5. 判据（预注册，不得事后修改）

### 5.0 对照有效性闸门 R0（v1.2 新增，先于一切判定）

**REG 臂只有在自身有效时才参与颜色依赖判定。** 判据：

```
有效 ⇔ reg_by_label 单步命中（3 种子均值）≥ 0.50
```

- `reg_by_label < 0.50` → REG 判为**不可解释对照**：只报告数值，**不进入**任何颜色依赖判定；
- 此时 M3 的结论范围自动收窄为"`cls` 的颜色依赖"，并必须写明"REG 无法判断"。

理由（smoke 证据）：`by_label + reg` 单步命中 **0.016**、任务成功率 **0.000** ——
REG 在**颜色消融之前**就已经在地板。若不设此闸门，
"`reg_permuted ≤ 0.10`"会被 REG 的训练失败自动满足，**把失效误判成颜色捷径**。

### 5.1 主语判据：**配对效应 Δ**（v1.5 改为以此为主）

记每种子均值 `m_s(by_label)`、`m_s(permuted)`，配对差 `Δ_s = m_s(by_label) − m_s(permuted)`（s=0,1,2）。

**主结论看 Δ，不比较两个边缘区间是否重叠**（配对设计下比区间重叠更贴合问题）。

| 结论 | 条件 |
|---|---|
| **强颜色依赖** | `Δ̅ ≥ 0.50` 且 Δ 的 95% CI **下限 > 0**，且 `cls_permuted` 保守值（3 个种子里最大）`≤ 0.10`，且 `cls_by_label` 保守值（最小）`≥ 0.80` |
| **中等依赖** | `Δ̅ ≥ 0.20` 但未达"强" |
| **弱/无依赖** | Δ 的 95% CI **上限 < 0.15** 且 `cls_permuted` 保守值 `≥ 0.85` 且 `cls_by_label` 保守值 `≥ 0.80` |
| **无法判断** | `cls_by_label` 保守值 `< 0.80`；或 `CI_Δ` **全宽**（上限 − 下限）`> 0.40`（等价于半宽 > 0.20）；或 `run_noise_high` 影响判定 |

REG 的角色（R0 通过时）仅作**佐证**，不进入上述判定。

### 5.2 附带判据

若 `cls_permuted` 落在随机水平（≈1/36=0.028）且 `cls_by_label ≥ 0.80`，
必须在结论里写明"这是**颜色是唯一可用线索**的证据"，而**不是**"模型接地能力差"。

### 5.3 统计口径（v1.5：三层不确定性 + 配对效应）

**硬规则：6 次训练不是 6 个独立观测。** 两个 repeat 嵌套在同一 seed 内，不可直接合并算 CI。

#### 5.3.1 三层不确定性（必须分开报）

| 层 | 记号 | 估计方式 | 自由度 | 含义 |
|---|---|---|---|---|
| **运行噪声** | `σ²_run` | 每格：`σ²_run = (1/3) Σ_{s=0}^{2} (r_{s1} − r_{s2})² / 2` | **df = 3**（3 个独立差值） | 同配置重跑的不稳定性 |
| **观测到的种子均值离散** | `var(m_s)` | 3 个 `m_s` 的样本方差 | df = 2 | **混合量**：≈ `σ²_seed + σ²_run/2` |
| **种子效应（参考）** | `σ²_seed` | `max(0, var(m_s) − σ²_run/2)` | 不单独检验 | **仅作参考**（n=3 时极不稳定，不用于判定） |

> **自由度说明（v1.6 修正）**：`σ²_run` 是**逐格**估计（一格 = 3 seed × 2 repeat = 3 个重复差值），
> 因此 **df = 3**，不是 4。若将来把 4 个格合并估一个全局噪声（12 个差值，df=12），
> 必须在结果里写明"合并了哪几格、共几个差值"，否则不得使用合并值。

**关键澄清**：`var(m_s)` **不是"纯种子间方差"**，它已经把运行噪声包含在内。
因此本实验**不**声称能干净分离"种子效应"，只声明"以种子为单位的总不确定性"。

#### 5.3.2 配对效应 Δ（主结论）

对每个 seed 计算 `Δ_s = m_s(by_label) − m_s(permuted)`，然后：

```
Δ̅   = mean_s(Δ_s)
sd_Δ = sd_s(Δ_s)                    （n=3）
CI_Δ = Δ̅ ± t(0.975, df=2) × sd_Δ/√3
```

必须同时报告：**三个 Δ_s 的逐点值**、`Δ̅`、`sd_Δ`、`CI_Δ`、以及 CI 的下限（保守端）。

**"CI 宽度"的定义（v1.6 明确）**：一律指**全宽** `上限 − 下限`；
判据里的 `> 0.40` 即全宽超过 0.40（半宽超过 0.20）。报告时必须同时给出上下限，避免歧义。

#### 5.3.3 报告的固定清单（缺一即视为结果无效）

1. 每格 6 个原始值（4 格 × 6 = 24 个数）；
2. 每 seed 的两重复差值 `d_s` 与 `σ²_run`；
3. 每格的 `m_s`（3 个）与 `var(m_s)`；
4. `Δ_s`（3 个）、`Δ̅`、`sd_Δ`、`CI_Δ`；
5. `σ²_seed` 的参考估计（并注明不稳定）；
6. 是否出现 `run_noise_high` 及其对判定的影响。

**不使用 bootstrap**：n=3 时重采样不可靠，统一用 t 区间（df=2）。

#### 5.3.4 关于 0.146 极差

那只是**初步噪声警报**（单配置、3 次运行、quick 规模），不得当作全实验通用地板；
正式结果以本实验测到的 `σ²_run` 为准。

### 5.4 重复冲突的裁定规则（不得靠追加训练解决）

| 情况 | 处理 |
|---|---|
| 某格 `d_s > 0.10`（两次重复差过大） | 该格标记 `run_noise_high`，在结果里明示 |
| `run_noise_high` 影响到阈值判定（例如让 `cls_permuted` 跨过 0.10） | 该假设判为**无法判断**，并写明"运行噪声大于效应" |
| 只有个别格噪声大、其余稳定 | 报告时逐格标注，不整体推翻 |
| **某个 seed 明显偏离另外两个** | **不得删除该 seed，也不得只报另外两个**；必须原样报出 3 个 `Δ_s` 与 `m_s`，并在解释里说明离散度 |

**禁止**：根据中途结果追加重复次数或改判据。24 次跑完即为终点，不追加训练、不挑选种子。

| 项 | 值 |

| Python | 3.12.10 |
| PyTorch | **2.11.0+cu128** |

| cuDNN | 91900 |

| `cudnn.benchmark` | **False** |

| `torch.use_deterministic_algorithms` | **False** |
| `CUBLAS_WORKSPACE_CONFIG` | 未设置 |

### 10.1 为什么不开确定性模式

尝试 `torch.use_deterministic_algorithms(True)` 直接失败（原文）：

```
RuntimeError: adaptive_avg_pool2d_backward_cuda does not have a deterministic
implementation, but you set 'torch.use_deterministic_algorithms(True)'.
You can turn off determinism just for this operation, or you can use the
'warn_only=True' option, if that's acceptable for your application.
```

`cls` 头的 `adaptive_avg_pool2d` 在 CUDA 上没有确定性反向实现。

### 10.2 为什么不换 CPU / 不替换算子

- 换 CPU：单轮慢约 10×，且与 P0/P1 的 GPU 结果环境不同，跨文件不可比；
- 替换 `adaptive_avg_pool2d`：会改变模型结构，等于引入新的自变量，
  与"只做颜色消融"的设计冲突。

→ 结论：**把非确定性当作测量对象的一部分**，用重复运行显式估计（§5.3），
而不是为了漂亮的可复现性去改模型。

### 10.3 已知限制

- 因此本实验的 CI 以**种子**为单位（n=3），并把 `σ_within` 单独报告；
- 任何跨论文/跨实验的数值比较都要先看噪声地板是否小于效应。
