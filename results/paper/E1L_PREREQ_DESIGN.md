## 0. 目标

E1-L 现在缺的不是训练次数，而是**可测窗口**：

| 头 | 现状（`EVIDENCE_GAPS.md` §7.3） | 后果 |
|---|---|---|
| `cls` | 全 H 饱和 | 无动态范围，测不出"接地能力随规模变化" |
| `reg` | H≥4 全地板（≤0.087） | 长 H 落在死角，而 crossing 必须在长 H 观察 |

本文只回答一件事：**M1/M2/M3 各自用什么最小实验、按什么判据算"满足"。**
满足之前，E1-L 的 36 次训练不启动。

## 1. 关键算术（决定了目标值，不是拍脑袋）

设单步正确率 `p` 在 H 步间近似独立，则任务成功率 ≈ `p^H`。要让 **H=1,2,4,8 全部**落在 [0.2, 0.9]：

```
p^8 ≥ 0.2  →  p ≥ 0.817        （否则 H=8 掉出下限）
p^1 ≤ 0.9  →  p ≤ 0.900        （否则 H=1 顶出上限）
⇒ p ∈ [0.817, 0.900]，目标 p ≈ 0.86
```

**推论**：M1 不是"把难度调大"，而是**把单步正确率精确压到 0.86 附近**。
当前 `cls` 的 p ≈ 0.98（P3 H1=0.980）——差 12 个点；这正是全部问题所在。

## 2. 候选难度轴（按"是否已有证据"排序）

| # | 轴 | 已有实测（单步 p） | 评价 |
|---|---|---|---|
| **A1** | **干扰项密度 d**（H4） | d=0:0.938 / 1:0.533 / 2:0.362 / 4:0.302（w4） | ✅ **已验证能大幅移动 p**；且不改标签/颜色映射 |
| **A2** | **width w**（H4 同表） | d=1 时：w4 0.533 → w8 0.636 → w12 0.802 → w16 0.877 → w32 0.896 | ✅ 与 A1 正交，可组合到 p≈0.86 |
| A3 | `fill`（元素占比） | 无效（C6） | ❌ 已否证 |
| A4 | grid 6→8 | H3b：8×8 单步 ≈0.50（w32） | ⚠️ 会改变任务族，作为备选 |
| A5 | ρ（漂移） | P1 已用 | ⚠️ 只影响长 H，不能单独把 H=1 压下来 |

**结论**：M1 的首选配置不是"新发明一个轴"，而是**组合两个已验证的轴**。
按 H4 实测，**(d=1, w16)** 的单步 p ≈ **0.877**（3 seed：0.897 / 0.858 / 0.876），
代入 `p^H` 得 **预测值** H1 0.877、H2 0.769、H4 0.592、H8 0.350 —— 四点全在 [0.2,0.9] 内。

> ⚠️ `p^H` 是**独立步假设**下的预测，不是结论：ρ=0.3 的漂移、以及错误标记的可见性都会让它偏离。
> 所以 M1 必须**实测** H 曲线再过门禁，不能拿这张表当通过依据。

### 2.1 M1 需要的最小 harness（约 80 行，新文件）

H4 的 runner 只有单步（训练与评估都是），M1 需要多步 rollout：

```
复用：h4_density.render_cond / gen_decoys / make_bg（渲染 + 干扰项）
复用：p3_env.make_episode / fresh_labels（H 步目标序列 + ρ 漂移）
参考：h3b_generalization.rollout 的控制流（逐步执行、失败即止）——**复制逻辑，不 import**
新写：把 render_cond 接进 rollout 的渲染调用（约 30 行）
不改：p3_verifier.py、p3_env.py、h4_density.py
```

输出：`results/paper/e1l_m1_prescan.jsonl`（一行一个 (候选, seed, H, ρ)）。

**已实现**：`experiments/paper/e1l_m1_prescan.py`（约 330 行，含渲染 + 脚本 + rollout + 统计）
+ `experiments/paper/test_e1l_m1_prescan.py`（11 个逻辑测试，不训练）。
渲染器契约：`flat + d=0 + bar_total=H` 时必须与 `p3_env.render_ui` **逐像素相同**（有测试保证）。

**进度条口径的一处刻意修改**：进度条默认按 **H_MAX=8** 着色（`bar_total=H_MAX`），
不按当前评估用的 H。否则同一 `progress` 在 H=4 与 H=8 下会画出不同长度的条，
观测分布随 H 变化，"同一任务只改 rollout 长度"就不成立（该问题由前缀一致性测试发现）。

## 3. M1 预扫描（设计）

| 项 | 设定 |
|---|---|
| 目的 | 找到 `(d, w)` 使 H=1..8 全部落在 [0.2,0.9]（含 margin 0.05） |
| 候选 | **`d1w8` / `d1w12` / `d1w16` / `d1w24`**（全部 d=1，均为 H4 已验证条件；`d=0.5` 已按裁定 22 撤回，不作为本次候选） |
| 训练 | 每候选 × 3 seed；**H 是评估参数，不重训**（同一模型评估 H=1,2,4,8 × ρ∈{0, 0.3}） |
| 任务数 | **500 / (候选, seed, H)**（裁定 22 批准；只增加评估量，不增加训练） |
| 运行数 | 4 候选 × 3 seed = **12 次短训练**（w8–w24，约 10–25 s/次） |
| 数据 | 复用 `h4_density.py` 的生成器（配对任务流，`config_fp` 记录） |
| 判据 | 门禁 **B 模式**：`--band 0.2,0.9 --margin 0.05 --monotone --monotone-dir down`；**ρ=0.3 与 ρ=0.0 两套曲线都必须过**（`cond` 带 `@r0.3` / `@r0.0` 标签） |
| 输出 | `results/paper/E1L_M1_PRESCAN.jsonl` + 门禁报告 |


### 3.0 执行命令（裁定 23 修正后，唯一版本）

```powershell
# 12 次训练 + 96 格评估（4 候选 × 3 seed × 2 ρ × 4 H）
python experiments/paper/e1l_m1_prescan.py --stage full --tasks 500 `
  --seeds 0,1,2 --rhos 0.3,0.0 --out results/paper/e1l_m1_prescan.jsonl

# 两套 ρ 曲线一起过门禁（cond 已带 @r0.3 / @r0.0）
python experiments/paper/prescan_gate.py --runs results/paper/e1l_m1_prescan_gate.jsonl `
  --band 0.2,0.9 --margin 0.05 --monotone --monotone-dir down
```

`--rho`（单值）已废弃：它只评估一个 ρ，会让"对照条件"变成口头承诺。
现在 `--rhos` 是列表，且 full 模式结束时会自检 `4×3×2×4=96` 行是否齐全，缺一行即 exit 1。

### 3.1 运行前锁定的配置（裁定 22）

| 项 | 锁定值 |
|---|---|
| 候选（4 个，全部 d=1） | `d1w8`、`d1w12`、`d1w16`、`d1w24` |
| seed | `0, 1, 2` |
| 任务数 | **500** / (候选, seed, H) |
| H | `1, 2, 4, 8` |
| ρ | `0.3`（主）、`0.0`（对照，仅用于判断 H 曲线是否由漂移主导） |
| 训练 | 3000 样本 / 20 epochs / Adam 3e-3 / batch 64（与 H4 同） |
| 门禁 | `--band 0.2,0.9 --margin 0.05 --monotone`，**逐 seed** 检查 |
| 训练次数 | **12**（4 × 3），不追加 |

`d=0.5` 撤回理由（裁定 22）：它是**新的操作化条件**（平均密度），
不是 H4 已测条件；引入它等于在预扫描里偷偷换题目。若四个候选全不通过，
结束本轮、另立预扫描设计。

### 3.2 状态机口径（裁定 22 的确认项）

| 量 | 作用域 | ρ 漂移时 |
|---|---|---|
| `progress` | **任务的累计完成数**（0..H） | **保留** |
| `done[slot]` | **当前布局**中"已点过这个格子" | 清零（布局换了，旧格子不再指同一元素） |
| `wrong[slot]` | **当前布局**中"误点过这个格子" | 清零 |

不变量（由 `test_progress_is_cumulative_done_is_per_layout` 断言）：
`progress == 前 t 步正确数`、`success ⇔ progress == H`、漂移步的 `done/wrong` 必须全空。
与 `p3_env` / `h3b` 的语义一致：**漂移只重置标记，不重置进度**。

由此记录一条实验边界：

> **B-drift**：ρ=0.3 时约 30% 的步会清掉错误标记，误差累积被环境语义削弱；
> 这是**当前环境机制的一部分**，本轮不改（改了就变成新的实验条件）。

### 3.3 评估顺序无关性

`build_scripts` 与 `decoy_seed` 只依赖 `(seed, task, t, d, ρ)`，不依赖 H，也不依赖评估顺序；
由 `test_eval_order_independence` 断言（先 H4 后 H8 与先 H8 后 H4 结果相同）。

---

**判定**：

| 结果 | 动作 |
|---|---|
| 某候选在 ρ=0 与 ρ=0.3 下都过 B1 | **M1 满足** → 该配置成为 E1-L 的固定设置 |
| 仅 ρ=0 通过 | M1 部分满足；E1-L 只能跑 ρ=0，需改预注册（另立） |
| 全部不通过 | 转 A4（grid 8×8）或 M2；**不为了通过而加宽 band** |

## 4. M2（`reg` 塌陷）最小诊断

`reg` 在 H≥4 ≤0.087，先分清是**表示问题**还是**累积问题**。三个互斥假设：

| 假设 | 判别实验 | 若成立的读数 |
|---|---|---|
| H-a 输出/目标尺度问题 | `reg` 在 H=1 的误差 vs 机会水平（随机点） | H=1 就已≈机会 → 表示/损失问题，与记忆无关 |
| H-b 分辨率不足（元素 4–8 px） | 同配置 `img_size=320`，H=1，1 seed | 误差显著下降 → 提高分辨率即可，不是机制问题 |
| H-c 多步误差累积 | H=1 正常、H=2 明显掉、H=4 地板 | 纯累积 → 需要"重试/验证"类机制（H3b 已有），不是 M2 能修的 |

成本：**2 次短训练**（H-a 复用现有权重即可，H-b 需 1 次）。M2 只做到"分清类型"，不做修复。

## 5. M3（指标 ↔ 接地能力 的消融证据）

要求：**移除一种接地线索 → 指标必须下降**，否则该指标不是在度量接地。

| 因子 | 实现 | 状态 |
|---|---|---|
| 颜色 | `EnvCfg(color_mode="permuted")`（M3 实验已做） | ✅ **已完成**：Δ̅=0.9718，CI [0.9711,0.9726] |
| 形状 | 渲染层加 `shape ∈ {rect, circle}`，指令指定形状 | ❌ 待做（约 30 行） |
| 位置 | 所有元素排成一行（位置不再是线索） | ❌ 待做（约 15 行） |

**判定**：颜色已证；形状/位置若同样导致显著下降 → M3 满足。
若某因子无影响 → 记为"该因子在此渲染下不是线索"，**不算失败**，但 M3 只覆盖已证实维度。

## 6. 门禁与停止规则

1. **先预扫描，后主实验**：M1 的 12 次预扫描过 B 模式门禁后，才讨论 E1-L 的 36 次；
2. 预扫描数据**不进** E1-L 主分析（`prescan` 命名，单独文件）；
3. 不追加 band、不追加候选、不追加 seed；
4. M1 与 M2 **不并联**：先 M1，M1 不通过再看 M2（避免"哪个好看用哪个"）；
5. 任何一步失败 → 记录为"前置未满足"，E1-L 继续暂停。
