# QGIS W1：真桌面应用上的第一轮

> 复现：`python experiments/qgis/qgis_bridge/run_w1.py`（QGIS 3.44.15，桥在 127.0.0.1:8765）
> 数据：`experiments/qgis/qgis_bridge/w1_results.json`

---

## 1. 这轮在验证什么

窄域路线的第一个**真桌面应用**（不是网页、不是自建沙箱）：
任务由 **GUI 动作**执行，成功由 **PyQGIS 状态**判定（外部真值，不是"点了就算"）。

## 2. 结果

### 2.1 oracle 冒烟：4 任务 × 2 轮，**全成功**

| 任务 | 执行（结构化动作） | 真值判据 | 观测到的真值 |
|---|---|---|---|
| activate_zoom_in | 触发 `Zoom In` | `canvas.mapTool()` | `'Zoom In'` ✅ |
| activate_pan | 触发 `Pan Map` | `canvas.mapTool()` | `'Pan Map'` ✅ |
| zoom_full | 先把视图缩到 30%，触发 `Zoom Full` | canvas extent 复原 | 与复位参考差 < 1.0 ✅ |
| toggle_console | 触发 `Python Console` | 控制台可见性 | False→True→False ✅ |

> 一个真坑：QGIS 的 `Zoom In/Out` 是**地图工具**（`QgsMapToolZoom`），触发只切工具、
> 不立刻缩放；`Zoom Full` 才是一次性动作。判据必须按"工具"而不是"比例"写。

### 2.2 候选统计

- 工具栏动作（带坐标）：**67 个**
- 按钮尺寸：median **32×31 px**，min **24×23 px**（窗口 2560×1369）
- 这正是 H4 的"结构化同类干扰"密集区：**又多又小又像**

### 2.3 两条通道

| 通道 | 结果 |
|---|---|
| **结构**（动作名关键词 → 选动作） | **4/4** |
| **像素**（按钮外观 67 类分类，train/test 按按钮划分） | train 0.113 / **test 0.000**（chance 0.015） |

像素那一行只是**上界探针**（只问"外观能不能区分按钮"）——它已经接近 0；
而真实任务要求的是"指令 → 按钮"，像素侧既读不到名字、也没有语义，
**在这个 24–32px 的图标阵列里基本不可能**。

---

## 4. 局限（这轮**不是**端到端像素 agent）

1. **动作是特权 Qt**（`QAction.trigger()`），**没有真的动鼠标**——测的是观测/选择，不是真实输入。
2. 任务是**单动作**的，没有多步、没有状态追踪（H1/H3 还没上）。
3. 结构侧是**关键词策略**，不是学习型（对比 `real_site_policy` 的 356/2600 样本结论）。
4. 像素侧只是**外观可分性上界探针**，不是像素策略。

# QGIS W2：多步 GUI 任务（`run_w2.py`）

> 复现：`python experiments/qgis/qgis_bridge/run_w2.py`　数据：`experiments/qgis/qgis_bridge/w2_results.json`

三个任务，**成功全部由 PyQGIS 状态判定**（不是"点了就算"）：

| 任务 | 步骤（真 GUI 动作） | 真值判据 | 结果 | 耗时 |
|---|---|---|---|---|
| **select_by_expression** | ① 触发菜单动作 `Select Features by Expression…` ② 往表达式编辑器（**QScintilla**）写入 `"pop" > 1000000` ③ 点 `Select Features` | `selected == 2` | ✅ 3/3 步 | 1658 ms |
| **toggle_visibility** | 图层树里选中行 + **真键盘 Space** | `visible` 翻转 | ✅ | 183 ms |
| **select_all_deselect** | ① `Select All Features` ② `Deselect Features from All Layers` | `5 → 0` | ✅ | 243 ms |

**这轮踩到的真坑（都已修）**

1. QGIS 的 `Zoom In/Out` 是**地图工具**，触发只切工具 → 判据必须用 `canvas.mapTool()`，不是 `scale`。
2. 菜单动作**需要图层是"当前图层"**才启用：`activate_layer()` 先把图层树里的行设为 current，`Select Features by Expression…` 才可用。
3. 动作真名要探：不是 `Select by Expression`，而是 **`Select Features by Expression…`**；取消选择是 **`Deselect Features from All Layers`**（`find_actions(substr)` 就是为这个加的）。
4. 表达式编辑器是 **QScintilla**（没有 `setPlainText`），写入要走 `setText` → 文本 op 现在依次尝试 `setPlainText/setText/setValue`。
5. 图层树复选框**点不到**（缩进吃掉左缘，`visualRect` 甚至返回空）→ 改用"选中行 + **真键盘 Space**"，188 ms 完成，且是真输入。

**含义**：真桌面应用上，"多步 + 对话框 + 真键盘"的 GUI 任务可以被**状态判定**闭环；
下一步才能在同一套任务上比较 **struct / pixel / hybrid** 三条臂，并首次把 **H1（重观察）/ H3（结果验证）**搬到真应用上。

# QGIS W3：学习型结构策略 vs 关键词（`run_w3.py`）

> 复现：`python experiments/qgis/qgis_bridge/run_w3.py`　数据：`experiments/qgis/qgis_bridge/w3_results.json`
> 动作空间来自 QGIS 自己：`find_actions("")` → **583 个动作**

| split | learned | keyword |
|---|---|---|
| 指令→动作（**训练见过**的动作名） | **1.000** | — |
| 指令→动作（**未见**动作名） | **0.043** | **0.897** |
| 润色指令（零样本，6 条） | 1/6 | 1/6 |
| chance | 0.0017 | |

**读法**

1. **学习型策略是"背名字"**：训练动作 100%，换未见动作名 **4.3%**（仅略高于 chance 0.17%）。
   这与 `real_site_policy`（站点级 0.184→0.386）、`WinSim W5/W11`（未见应用 0）**同一条曲线**：
   **小数据下的学习型结构策略不泛化**。
2. **关键词在"指令=动作名"上天然强（0.897）**——因为字符串就是同一个；
   这不是学习型策略的公平对手，但恰好说明**在这类任务里"名字"本身就是最强的特征**。
3. **润色指令两边都差（1/6）**：指令与动作名不同字面时，
   关键词靠词重叠（"tool"命中了 "Add Model to Toolbar"），
   学习型模型也没学到语义（"zoom in the tool" → "Clear"）。
   ⇒ **"指令→动作"的语义映射，靠 583 个样本学不出来。**

**结论（与全项目一致）**：结构通道的价值在**可用性**（动作名就在那里），
不在"小模型学会选"；要学，需要的是**数量级更多的任务/指令对**，而不是更大的模型。

# QGIS W4：真鼠标臂 —— H1（重观察）在真桌面应用上的第一刀

> 复现：`python experiments/qgis/qgis_bridge/run_w4.py`　数据：`experiments/qgis/qgis_bridge/w4_results.json`
> （会短暂占用鼠标；脚本 FAILSAFE + 指针复位）

同一目标（工具栏 `Zoom Full`），真值一律看 `canvas extent`：

| 情形 | 过程 | extent[0] | 结果 | 耗时 |
|---|---|---|---|---|
| **A 新鲜坐标** | 取按钮 rect 后**立刻**点 | 7.66 → **5.61**（=参考） | ✅ | 821 ms |
| **B 过期坐标** | 取 rect → **改窗口大小** → 点旧坐标 | 7.66 → 8.50 | ❌ | 812 ms |
| **C 盲点** | 无坐标，固定在画布中部点 | 8.53 → 9.34 | ❌ | 810 ms |

**两条要点**

1. **过期坐标不是"点了没反应"，而是"点中了旁边的按钮"**（8.50 > 参考，说明打到了 *Zoom Out*）。
   即：**静默错误**——手指动对了、点下去的也是真按钮，只是不是目标那个。
   这正是 H1 的机制在真桌面上的形式：**不重新观察，就会自信地做错事**。
2. **真鼠标单步 ~810 ms**，比特权动作/真键盘（~180 ms）**贵 4–5 倍**。
   这是"真输入"的代价轴，之前 WinSim 的成本模型（观察 4.45 vs 结构 1.25）在这里得到外部印证。

**至此 QGIS 线三项顺序任务全部完成**：
多步任务（真值判定）→ 学习型结构策略（不泛化）→ 真鼠标臂（H1 成立）。

# QGIS W5：H3（结果验证）在真桌面应用上

> 复现：`python experiments/qgis/qgis_bridge/run_w5.py`　数据：`experiments/qgis/qgis_bridge/w5_results.json`

**设计**（P3/P6 的机制搬到真应用）：同一目标 `Zoom Full`，策略 50% 触发正确动作、
50% 触发错误动作（`Zoom Out/In`、`Pan Map`…）。每组记录
**(动作前, 动作后) 地图区截图**（256×128）+ 真值标签（extent 是否恢复）。
训一个小 V 判断"这次动作有没有让状态推进"——**V 用的是 π 拿不到的信息（后果）**。

| 指标 | 结果 |
|---|---|
| 样本 | 140（成功 70 / 失败 70） |
| **V 的 AUC（阈值无关）** | **1.000** |
| V（默认阈值 0.5） | acc 0.514，**FNR 0.000 / FPR 1.000**（恒说"成功"） |
| **V（验证集阈值校准后 t=0.51）** | **acc 1.000，FNR 0.000 / FPR 0.000** |
| 门控重试（≤3 次）：无 V → 有 V | 0.870 → **0.871（+0.000）** |

**三条结论**

1. **H3 在真桌面应用上成立**：失败在"后果"里**完全可见**（AUC = 1.000）。
2. **但默认阈值会把它毁掉**：0.5 阈值下 V 恒说成功（FPR=1）。
   这正是 **P6 的方法论**——**看 AUC，不看固定阈值的准确率**；校准后 acc 1.0。
3. **门控"盲目重试"没有增益**（+0.000）：因为重试是**独立重掷**，上限就是 `1-(1-q)³ = 0.875`，
   有没有 V 都一样。**V 的价值是"知道失败了"**——这在步数有代价、或长 horizon
   必须止损时才兑现（正是 P3 测到的形式），而不是靠重掷。

**QGIS 线完整收束**：W1 通道对照 → W2 多步任务 → W3 学习型结构策略 → W4 真鼠标/H1 → W5 结果验证/H3。
主假设的四个机制里，**H1（重观察）与 H3（结果验证）现在都在真桌面应用上有了真值判定的证据**。
