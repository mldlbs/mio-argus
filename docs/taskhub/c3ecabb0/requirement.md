## 1. 背景与问题
- 现状：模型线（MioArgus v3）只在静态数据集上评测（504 条 balanced：动作 100% / 坐标 MAE 0.0667），从未驱动真应用。
- 现状：QGIS 线（W1–W27）有真值通道（bridge truth：extent/scale/tool/renderer）与确定性脚本机械，但脚本不是模型。
- 痛点：两条线未合流——"截图→模型→点鼠标→看结果"的真闭环从未在真应用上跑过，产品形态（模型自己看屏干活）实际不存在。
- 证据：W28 首测（2026-10-03，run `43731559`）证实 v3 在真 QGIS 截图上零样本动作准确率 0%（18/18 预测 scroll）、坐标命中率 0%（中位偏差 475.6px）；同代码在自家数据上 20/20 正确 ⇒ 差距是真实的域差距。
- 为什么现在做：QGIS 机械（W23–W27）与安全执行器已就绪，示范数据可用脚本自动生成（零人工），合流成本已降到可执行。

## 2. 目标与非目标
- 目标：
  - G1 接通"截图 → 模型 → 动作 → 执行 → 再截图"闭环（真应用 QGIS；安全区约束；bridge 真值判定）。
  - G2 量化零样本差距（W28 基线已给：动作 0% / 坐标命中 0% / 中位偏差 475.6px）。
  - G3 用 W23–W27 确定性链当老师自动产真 UI 示范数据（W29，≥2k 步），LoRA 微调后度量增益（W30）。
  - G4 带验证器的真任务闭环：任务成功率 + 正确产物/分钟，对照脚本基线（W31）。
- 非目标（本次明确不做）：
  - 训练更大模型（保持 v3 规模，只做 LoRA 微调）。
  - 通用桌面 / 多应用泛化（只做 QGIS 单应用；VM 合成桌面仅作对照）。
  - 自然语言自由规划（任务指令限定为模板化英文短句）。

## 3. 用户故事 / 使用场景
- 作为研究者，我想让 v3 在真 QGIS 上完成 Zoom Full / Zoom Last / 选择导出这类单步与多步任务，以便量化模型驱动真应用的可用性。
- 作为工程链维护者，我想在跑 W23–W27 确定性链时自动记录示范数据，以便零人工标注地扩充真 UI 训练集。
- 作为评估者，我想用 bridge 真值自动判定每步成败并给出成本，以便得到可复现的成功率与"正确产物/分钟"。

## 4. 功能需求

| FR-1 | 闭环执行器：截图→模型推理→动作解析→安全执行（越界不点）→再截图 | P0 | 3 试 0 次越界点击；每步落盘 pred/clicked/truth/fail |

| FR-4 | 示范数据采集：确定性链运行中录制 (截图, 指令, 动作, 坐标, 后状态) | P0 | ≥2k 步；格式符合 data-model；train/val 划分落盘 |
| FR-5 | LoRA 微调 + 重测：W29 数据微调后重跑 FR-2/FR-3 同题对照 | P0 | 增益表落盘；原 504 条评测集无回归（±0.02） |
| FR-6 | 真任务闭环：模型驱动 + 验证器 + 失败重试，对照脚本基线 | P1 | 任务成功率与正确产物/分钟落盘；≥3 试；失败归因 |

## 5. 非功能需求
- 性能：
  - 单步推理 ≤ 500 ms（GPU）；单步闭环（截图+推理+执行+判定）≤ 3 s。
  - W29 数据采集吞吐 ≥ 200 步/小时（脚本链天然节奏）。
- 安全：
  - 点击仅允许落在 QGIS 主窗口矩形内；非 click 动作不执行；动作白名单 click/scroll。
  - 不允许触碰宿主机其他窗口（安全门硬约束）。
- 兼容 / 依赖：
  - Windows + QGIS 3.44 + qgis_bridge（PYQGIS_STARTUP 启动）；transformers 离线缓存；CUDA 可用。

## 6. 边界与约束
- 时间 / 资源：单机、单 GPU；单个 W 任务 ≤ 2 小时（含采集/训练/评测）。
- 合规要求：无（本地实验；不涉外部服务）。
- 既有系统约束：复用 qgis_bridge（运行产物就地保存）；结果 json 写 results/computer_use/；示范数据写 artifacts/（gitignored）。
