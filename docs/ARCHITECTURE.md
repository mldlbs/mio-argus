> **日期**：2026-09-19

## 0. 一句话

标准 CUA 架构的输出是**动作**；Argus-IS 的输出是**"当前信息是否足够决定动作"**。

- 信息足够 → 输出动作（选择 / 点击）
- 信息不足 → 输出**感知动作**（去哪里看、看多细、是否重观察）

> **参数预算从"记住世界"改判给"决定还需恢复什么信息"。**

这不是一句口号，而是可检验的：架构里必须存在一个显式的**充分性变量 `σ`**，
并且它必须真的改变行为（触发感知、触发重试），否则它就是零。

| 被排除的路线 | 为什么 | 证据 |
|---|---|---|

## 1.5 先验工作：本文档不主张什么（v0.2 新增）

v0.1 写"环境无检索能力，delta 待核实"。本轮已补检索，结论是**三个方向都已被做过**：

| 本文方向 | 已有等价工作 | 重合点 |
|---|---|---|
| A 粗 ROI → 细接地 | MEGA-GUI (arXiv 2511.13087)、DiMo-GUI (EMNLP 2025)、GUI-C² (arXiv 2605.30884) | 多阶段 + 模型自选缩放 + 收敛早停 |
| A 训练无关 zoom | ZoomClick (arXiv 2512.05941)、GUI-Lens (arXiv 2608.03270) | zoom 作为 GUI grounding 先验；GUI-Lens 直接引 Mnih 2014 |
| A/C 何时观察 | GUI-Eyes (AAAI-26)、AVP (CVPR 2026) | RL/agent 决定"是否/如何"调用 crop/zoom；AVP 原话即 "sufficiency" |
| C 充分性形式化 | "Learning to Decide with Just Enough" (arXiv 2510.01620) | 熵/互信息形式化 context sufficiency + regret bound |
| C 记忆–感知权衡 | PNAS Nexus 2026 | 人类在"记住 vs 再看"间权衡，即 H1 命题 |
| B 候选集选择 | UI-AGILE (arXiv 2507.22025) | 分解生成候选 + VLM adjudicate |
| 小模型胜大模型 | SE-GUI (NeurIPS 2025)、GUI-G1 (NeurIPS 2025)、GoClick | 3B/7B 数据高效超过 72B |

**因此**：本文档从"提出新架构"降级为"在一个统一形式化下做受控消融"。
`Argus-IS` 只用于指代这套对照实验，**不用于宣称机制首创**。

## 2. 统一形式化：把"信息充分性"设为一等变量

记：

| 符号 | 含义 |
|---|---|
| `o_t` | 观察（截图） |
| `g` | 指令 |
| `H_t = {h_1..h_m}` | 结构假设集（解析器候选框 / 元素列表） |
| `σ_θ(o_t, g, H_t) ∈ [0,1]` | **充分性**：`H_t` 是否包含目标且可识别 |
| `score_θ(h_i; o_t, g)` | 候选打分 |
| `p_t ∈ P` | 感知动作（重观察 / 裁剪 / 缩放） |
| `V_φ(o_t, o_{t+1})` | 结果验证（H3 形式 B） |
| `T` | 感知动作预算（glimpse 次数） |

决策规则：

```
if σ ≥ τ:   a_t = argmax_i score_θ(h_i)        # commit，成本 F_θ
else:       p_t ∈ P                            # perceive，成本 F_perceive
commit 后:  if V_φ(o_t, o_{t+1}) 未推进: 重新决策  # H3 闭环
```

端到端成本：

```
C = F_θ(commit 步数) + F_perceive(T) + F_φ(验证步数)
```

**核心主张（必须在 iso-FLOPs 下才成立）**：`H_t` 的恢复成本可以不由参数承担，
而由**顺序计算 + 环境**承担；`θ` 只负责 `σ` 与 `score` 两个小函数。

> ⚠️ 这个主张的天敌是"更多算力本来就更好"。若不在**等总算力**下比较（见 §3.4），
> "glimpse 赢一次性粗看"是平凡的，不构成机制证据。

三个方向分别是这条主张在三个量上的独立、可证伪的机制：

| 方向 | 作用的量 | 一句话 | 正面回应 |
|---|---|---|---|
| **A 主动变分辨率** | `H_t` 的获取方式 | 用顺序 glimpse 换分辨率，不换参数 | P8 §4.3 的分辨率瓶颈 |
| **B 对比式接地** | `score_θ(h_i)` 的结构 | 打分必须**相互比较**，而非各自独立 | H4 修正后的"结构化干扰" |
| **C 充分性闭环** | `σ` 与 `V_φ` 的耦合 | 用 H3 的信号决定何时触发 H1 | H1 与 H3 从未被同一个架构使用 |

## 3. 方向 A — 主动变分辨率接地（Active variable-resolution grounding）

### 3.1 被证伪的结论

P8：一次性检测器（`Detector`，backbone `stages=3` → 24×24 特征图）
在 `tiny` 布局（42 个 8–26px 元素）上 **recall 卡在 ~0.52**；
容量 24K→94K、训练 22→60 epoch **无改善**。P8 §5 自认唯一未排除的替代解释是
**分辨率**（24×24 特征图上一个小目标只占 1–3 个 cell）。

### 3.2 机制

把"一次性检测"换成**共享检测器上的迭代变分辨率**：

```
Step 0  粗pass：对下采样全图跑检测器 → 低分 objectness → top-K 粗候选
Step 1..T 对每个未解析候选：裁 W×W 局部窗口 → resize 到网络输入尺寸
          → 同一个检测器再看一次 → 更新候选框与置信度
Stop   置信度达标 或 T 耗尽
```

关键点：

1. **检测器权重在所有尺度共享** → 分辨率由顺序计算买。
   **但"不以参数为代价"必须在 iso-FLOPs 下验证**（§3.4），否则只是"算力换精度"。
2. 局部裁剪等价于把有效采样密度提高 `IMG_SIZE / W` 倍，
   直接回应 P8 的 24×24 瓶颈。
3. 与"更多截图"无关：不增加任何训练数据，只改变**推理时的观察路径**。

### 3.3 可证伪预测

- 同参数下，glimpse 检测器 recall **随 T 单调上升**；
- 存在有限 `T*`，使 `recall(T*) > reg_acc`；
- 从而 crossing：`total_params(det+sel) < reg_params` **且** `cls_par > reg`
  —— 与 P8 §2 完全相同的判据，直接对撞 P8 的 12/12 NO。

> ⚠️ 即使 crossing 成立，也只是**复现已知的主动感知结论**（§1.5）。
> 本方向的价值是用 P8 的否定作为**起点**，不是机制首创。

### 3.4 最小实验（P9）

复用 `p7_realistic_ui` 的环境、数据、`Selector`、`reg` 基线；
新增 `p9_active_zoom.py`：

| 配置 | 说明 | 控制什么 |
|---|---|---|
| `oneshot` | 复现 P8：全图检测一次 | 基线 |
| `glimpse-T` | T=1,2,3,5 的迭代缩放 | 待检验机制 |
| `random-crop-T` | 随机裁剪而非按置信度选窗口 | 排除"主动选择"，只留"分辨率" |
| `iso-flops-oneshot` | 一次性输入放大 / 通道加宽，总算力 = `glimpse-T` | **排除"更多算力本来就赢"** |

两条必须**同时**成立才叫机制证据：

1. `glimpse(T) > random-crop(T)` —— 增益来自**主动**选择看哪里；
2. `glimpse(T) > iso-flops-oneshot` —— 增益来自**顺序分配**，而非总算力。

- 只满足 (1) 不满足 (2) → 是"更多算力"，不是架构；
- 只满足 (2) 不满足 (1) → 是"上采样"，不是主动感知。

**P9 实测（2026-09-19，见 [results/paper/P9_RESULTS.md](..\results\paper\P9_RESULTS.md)）**：

- 条件 (1) **未通过**：`random-crop ≥ glimpse`（检测器引导的选窗不比随机好）；
- 条件 (2) 对 `mono-w`（只加宽通道）通过，但**对 `mono-R`（原生高分辨率）不通过**：
  补上 `mono-R` 臂后，等算力对比 **mono-R 胜 11/12**——
  tiny/micro@384（101.3M）**0.787/0.874** vs glimpse-3 **0.631/0.581**；
  extreme@288 只用一半算力 **0.919** vs glimpse-1 0.650。
- 结论：**顺序缩放的增益来自重采样分辨率/覆盖，与"主动"无关**；
  一旦单体被允许买原生分辨率，顺序缩放的优势消失。
  **方向 A 因此失去主要动机**（"一次看得很清 > 反复看同样清"）。
- 次生边界（**未解**）：`mono-R` 在 R=288/384 见顶、R=576 崩溃（0.24/0.65/0.71）；
  尝试在每个 R 复训均不稳定（从零欠拟合、热启动微调把 tiny/micro 打到 0.0），
  根因指向 `sz` 尺寸监督的设计缺陷（见 P9_RESULTS §4.3），**不能算结论**。
- 附带方法学坑：混入随机裁剪训练会破坏 BatchNorm，
  oracle 裁剪 recall 从 0.95 掉到 0.0（详见 P9_RESULTS §2.3）。

### 3.5 杀死条件

- recall 在所有 T 上仍 `≤ reg_acc` → P8 的"检测本身比回归难"成立，本方向证伪；
- 或参数增加使 `total ≥ reg_params` → "用小预算复活 H2"失败。

### 3.6 度量

recall vs T 曲线、首次越过 `reg_acc` 的 T、`cls_par`、总参数、IoU。
输出 `results/paper/p9_active_zoom_results.json` + `results/paper/P9_RESULTS.md`。

## 4. 方向 B — 对比式接地（Contrastive set grounding）

### 4.1 被证伪的结论

H4 机制修正（P5）：吃掉容量的**不是像素熵**，而是
**"与目标同类、需要被区分的结构化干扰"**。
但现有 `Selector` 的打分是**逐候选独立**的：

```
s_i = <q, pool(feat, box_i)> / sqrt(C)        # p7_realistic_ui.Selector
```

干扰项只要"自身看起来像目标"就会得到高分；argmax 只在两个分数接近时靠运气分开。
**架构里没有任何一项在显式执行"区分"这个动作。**

### 4.2 机制

把打分从**绝对**改成**关系式**：

```
f_i   = pool(feat, box_i)
s_i   = <q, f_i> + λ · Σ_j a_θ(f_i, f_j)      # a_θ: 集合内小注意力/双线性项
loss  = CE(s, y) + μ · hard-negative margin
```

两项改动：

1. **集合内交互**：让候选之间可以互相"减"，把干扰项的信息用起来；
2. **显式难负例**：按特征空间重叠度加权负例（正对应 H4 §"待量化的新指标"），
   并在环境里加入**同 label 干扰项**（目标 label 出现两次 → 必须靠上下文/空间区分）。

### 4.3 可证伪预测

- 在 P5 的 E2（低频色块）与 E3（自然背景）上，绝对打分者**从未达到 0.80**；
  对比式打分应在**更低参数量**下越过 0.80；
- 在 `tiny+texture` / `tiny+natural`（P7 中 `cls-parser` 大输）上，
  同参数下对比式 > 绝对式，并出现 `cls > reg` 的 crossing。

### 4.4 最小实验（P10）

复用 `p5_h4_entropy` 的背景分级与 `p7` 的自由布局；
新增同 label 干扰项开关。矩阵：

| 因子 | 取值 |
|---|---|
| 打分 | 绝对（对照） / 对比 |
| 背景 | E0 / E2 / E3、flat / texture / natural |
| 干扰 | 无 / 同 label 干扰 |

**参数必须配平**（给绝对打分基线补等量参数），否则不可比。

### 4.5 杀死条件

- 配平参数后，没有任何配置上对比式 > 绝对式 → 关系式打分无价值，本方向证伪；
- 或对比式只在同 label 干扰下有效、对 H4 的 E2/E3 无效 → 只解决了一个自造的问题。

### 4.6 度量

各配置成功率、达到 0.80 所需参数、干扰项–目标特征重叠度（新指标）、总参数。
输出 `results/paper/p10_contrastive_results.json` + `results/paper/P10_RESULTS.md`。

## 5. 方向 C — 信息充分性闭环（Information-sufficiency loop）

### 5.1 被证伪的结论

- H1（P1）：重观察替代参数，价值随 H 单调上升（`+0.29 → +0.65 → +0.92`）。
- H3（P3）：结果验证有效，V 小 17×，增益随 H 单调上升，已达 oracle 上界。
- P6：FNR 远比 FPR 有害，容错 `ε* ≈ 0.8 / H`，verifier 必须偏向接受。

**但这两条从未进入同一个架构**：P1 的闭环没有 verifier，P3 的 verifier 不决定何时重观察。
`σ`（充分性）这个量在项目里从未存在过。

### 5.2 机制

策略同时输出动作与充分性：

```
σ_t = σ_θ(o_t, g, H_t)
σ_t < τ  → 执行感知动作 p_t（重观察 / 换视角），不 commit
σ_t ≥ τ  → commit a_t
commit 后 → V_φ(o_t, o_{t+1})；未推进则重新进入决策
```

三处工程约束，全部来自已有实测：

1. `V_φ` 用**终局/进度信号**，不用重新接地的判别器（P2：后者与 π 同构）；
2. 阈值按验证集校准，不写死（P6 §1 的偶发崩溃根因）；
3. `V_φ` 校准偏向接受（P6：FNR ≪ FPR 的代价不对称）。

**感知必须定价，否则 C 退化为空**：若重观察/裁剪免费，`σ` 恒应触发感知，
最优策略就是"永远再看一眼"——P1 里 k=1 完全支配正是因为重观察几乎免费。
所以 P11 必须给 `p_t` 显式计费（例如每次感知 = 1 次前向，或按裁剪面积），
否则 `σ` 无论学成什么都无法与 baseline 区分。**这是本方向最容易做空的地方。**

### 5.3 可证伪预测

固定单步 FLOPs、固定参数，比较：

```
baseline:   σ ≡ 1（永不感知），无 V
+σ:         σ 触发感知，无 V
+σ+V:       完整闭环
```

crossing 定义：

```
S_σ+V(H) − S_baseline(H) > 0，且 gap 随 H 单调上升，存在有限 H*
```

同时 `C`（含额外感知步，且**感知按 §5.2 计费**）不得超过等算力单体——
否则"闭环成本抵消精度收益"（HYPOTHESIS §9.5）。
比较必须是 **iso-FLOPs**：baseline 用省下的感知算力换成更大 width / 更多步重试。

### 5.4 最小实验（P11）

复用 `p1_horizon` 的环境（H 扫描、ρ 变化）与 `p3_verifier` 的进度环境；
新增 `σ` 头与感知动作接口。扫描 `H ∈ {1,2,4,8}`、`ρ ∈ {0.3,1.0}`。

### 5.5 杀死条件

- 不存在 H 使 `S_σ+V − S_baseline > 0`；或
- 增益完全来自参数增加（配平后消失）；或
- `C` 超过等算力单体。

### 5.6 度量

`S(H)`、`C(H)`、crossing `H*`、纠正率、V 的 FNR/FPR。
输出 `results/paper/p11_sufficiency_results.json` + `results/paper/P11_RESULTS.md`。

## 6. 为什么这不是"更多截图 → 更大模型"

| 维度 | 旧路线 | Argus-IS |
|---|---|---|
| 输出 | 动作 | 先输出"信息够不够"，不够则输出感知动作 |
| 参数用途 | 记住世界（K_θ） | 估计充分性 σ + 关系式打分 |
| 分辨率成本 | 换更大 backbone | 顺序 glimpse（须在 iso-FLOPs 下证明，§3.4） |
| 干扰项 | 隐式靠 argmax | 显式集合内比较 + 难负例 |
| 闭环 | 无 | σ 触发感知，V 触发重试 |
| 新增数据 | 需要 | **不需要**（P9/P11 只改推理路径） |

> **注**：本表是"与本项目旧路线的差别"，**不是"与文献的差别"**。与文献的关系见 §1.5 / §9。

## 7. 实施顺序与验收

| 阶段 | 方向 | 脚本 | 判据（crossing） | 为什么这个顺序 |
|---|---|---|---|---|
| **P9** | A | `p9_active_zoom.py` | `total < reg_params` 且 `cls_par > reg` | 最便宜、最决定性；直接对撞 P8 的 12/12 NO |

**注（v0.2）**：三个方向均已有先验工作（§1.5）。本表用于**在本项目环境下确认机制与边界**，
不作为首创声明；论文级贡献应走 §9.2 的方法学 / 边界刻画路线。

**验收**：三个方向中**至少一个**出现 crossing。
只要有一个 crossing，就按项目纪律更新
[docs/HYPOTHESIS.md](HYPOTHESIS.md) / [docs/ROADMAP.md](ROADMAP.md) / [docs/REPORT.md]，
并保留负面结果与自我修正（REPORT §9 的规范）。

**若三个方向全部无 crossing**：则"信息充分性驱动"这条架构主张同样被证伪，
结论是 CUA 的瓶颈确实在**观测量本身**，而不是架构如何调度它——
这将是一个比"小模型能不能赢"更硬的负面结论，同样值得写进 REPORT。

## 8. 风险登记

| 风险 | 说明 | 缓解 |
|---|---|---|
| **A 的提升来自上采样而非主动** | 分辨率变高本身就可能提高 recall | `random-crop` 对照（§3.4） |
| **A 的 glimpse 循环不可并行** | 顺序计算换参数，延迟上升 | 报告端到端 FLOPs/latency，不只报成功率 |
| **B 的参数配平被质疑** | 对比项本身占参数 | 明确补参数量；报告"等参数"与"等精度"两条线 |
| **C 的 σ 退化为常数** | 学到 σ≡1，等于没有 | 监控 σ 分布；σ 必须有触发感知的实际比例 |
| **C 的额外步数抵消增益** | 闭环步数变多 | crossing 判据里硬性包含 `C` 不超基线 |
| **合成环境自欺** | P7/P8 已是自由布局+纹理，仍非真图 | 结论标注适用区间；a11y/DOM 作为另一条独立路径 |
| **σ 的监督从哪来** | 无 ground-truth "充分性" 标签 | 用"该观察下最终是否选对"作为弱监督；P9 先不引入 σ |

## 9. 与已有工作的关系（v0.2：已检索）

### 9.1 机制层面的重合（见 §1.5）

| 本文机制 | 已被覆盖 | 重合程度 |
|---|---|---|
| A 顺序变分辨率 | MEGA-GUI / ZoomClick / GUI-Lens / DiMo-GUI / GUI-C² | **高度重合，非原创** |

| B 集合内选择 | UI-AGILE / DETR 系 | 部分重合，增量有限 |

### 9.2 仍可能成立的差异化（证据等级 `[假设]`）

| 候选 delta | 为什么可能还站得住 | 验证方式 |
|---|---|---|
| **P7 不等式**在真实环境/API 上成立 | 把 `cls > reg ⟺ recall > reg_acc` 当**预测式**用；外部工作多是经验报告 | 真实环境复现 |
| **参数预算下的信息恢复下界** | 多数工作只报"更准"，不报"多少参数换多少信息" | 构造性下界实验 |
| **感知成本的权衡刻画** | "顺序感知何时不如一次性高分辨率"是边界/负向结论，竞争少 | iso-FLOPs 扫描 |

### 9.3 结论

**不再宣称任何"首次"。** 架构路线若要成立，必须落在 §9.2 的某一条上；
否则应转向方法学 / 边界刻画（见前一轮整体评估 §4）。
