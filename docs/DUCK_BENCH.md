## 1. 定位

**DUCK 是 MioArgus 的真实环境实验基准，不是游戏自动化项目。**

它存在的唯一理由：提供一个**可复现、可机械判定、可被证伪**的真实 GUI 环境，
用来测量"信息获取方式"与"模型规模"谁更决定任务表现。

### 1.1 是

- 一个带**自动初始化 / 自动评分 / 自动记录**的实验台；
- 一个**能区分 H1 是否成立**的对照实验装置；
- 一个产出结构化失败样本的来源（失败类型本身是数据）。

### 1.2 不是

- 不是"把鸭子养好"的机器人；
- 不是"看护体验优化"的产品；
- 不以增加游戏功能、优化策略、美化面板为研发目标。

### 1.3 实验场分工（B2 裁定，2026-11-17）

游戏没有复位入口，DUCK 的状态（鸭子、蛋板、玉米）都是玩家进度，无法回到同一初值。
因此**配对实验不成立**——记录协变量 + 交错执行也消不掉未观测状态差异。

裁定：

| 实验场 | 职责 | 可以得出的结论 |
|---|---|---|
| **合成 GUI**（P0–P9 已有） | A/B/C/D 完整对照、H1–H4 机制验证 | **因果结论** |
| **DUCK** | 真实环境运行、观察策略的效果、迁移失败模式 | **外部效度**，不是因果 |

推论：

1. **H1 的因果验证不在这里做**。A/B/C/D 四组在合成 GUI 中执行（§4 的设计原样搬过去）。
2. DUCK 上的观察频率实验仍有价值，但只能作为**真实环境观察策略研究**（准实验），不得替代 H1。
3. **不投入开发复位系统**。DUCK 的不可复现性是环境限制，不是待办项。

**冻结声明**：自本协议生效起，`duck_guard.py` 停止功能性扩张。
除"能提高测量可信度"或"能降低实验成本"的改动外，不再合入新功能。

## 3. 待验证假设

### H1（主线）：重观察替代参数

> 在固定动作空间与任务难度下，**提高观察频率带来的增益 ≥ 增大模型规模带来的增益**。

可证伪形式（预注册）：

| 结果 | 判定 |
|---|---|
| `B − A` 显著为正，且 `C − A` 不显著大于 `B − A` | H1 **未被否证** |
| `B − A` ≈ 0（观察频率无增益） | H1 **否证** |
| `C − A ≫ B − A` 且交互项 `(D−C) − (B−A)` 显著为负 | H1 **否证**（规模才是主导） |
| 交互项显著为正 | H1 只在"规模够大"时成立（**限定版 H1**） |

### 附带假设（可选项，不阻塞 Phase 0）

- **H2 动作空间压缩**：把动作空间从"像素坐标点击"换成"元素 id 点击"，成功率上升、无效动作率下降。
- **H4 窄域低熵**：同一策略在 DUCK 内的成功率显著高于在通用桌面任务上的成功率。

## 4. 实验因子与分组

### 4.1 两个因子

| 因子 | 水平 | 说明 |
|---|---|---|
| **模型规模** | 规则策略 / 小模型 / 大模型 | 见 §15 的阻塞项 |
| **观察频率** | 低频 / 事件触发 / 高频 | 定义见 §6 |

### 4.2 四组（预注册）

| 组 | 策略 | 观察策略 | 目的 |
|---|---|---|---|
| **A** | 小（规则或小模型） | 低频 | 基线 |
| **B** | 同 A | 高频 | 验证"重观察" |
| **C** | 大模型 | 低频 | 验证"参数规模" |
| **D** | 大模型 | 高频 | 验证交互效应 |

> **执行场说明（v0.3）**：A/B/C/D 四组在**合成 GUI** 中执行（那里可复位、可配对）。
> DUCK 只承接"真实环境下观察策略效果"的准实验，不承接本表的因果对照。

**Phase 0 只跑 A/B**（观察频率是纯测量变量，不依赖模型规模）。
C/D 在"可插拔策略 + 两个规模模型"就绪前**不得开跑**，也不得用 A/B 的结果替代。

### 4.3 必须固定的变量

- 任务族与难度（§5 同一版本）
- 动作空间（§7）
- 初始状态（§5.2）
- 运行环境（游戏版本、分辨率、窗口位置、系统版本）
- 每组样本量 **≥ 20**，A/B/C/D 交替执行以抵消时间漂移（`A B A B …` 交错，不整组连跑）

## 5. 任务族与终局判据

### 5.1 任务（每个任务一条可机械判定的终局条件）

| 任务 | 指令（给策略的自然语言） | 终局判据（机器可读） | 超时 |
|---|---|---|---|
| **T1 喂食** | "把 3 只等级≥5 的鸭子喂到不能再喂" | `count(duck: level≥5 ∧ maxed=true) ≥ 3` | 600 s |
| **T2 出售** | "把 1 只可卖的鸭子挂到市场" | `exists(market_listing.duck_id)` 且该鸭 `state=鸭子正在出售` | 900 s |
| **T3 合并** | "把蛋板最高等级提到 12" | `board.max_level ≥ 12` | 900 s |
| **T4 收爱心** | "收集本局所有爱心蛋" | `session.love_eggs ≥ K₀`（K₀ 由初始状态在 §5.2 中给定） | 600 s |

> 判据只允许**读取游戏状态**，不允许"看日志猜"。日志用于解释，不用于判分。

### 5.2 初始状态（可复现）

每次实验开始前必须写入并校验以下字段，**全部一致**才允许开跑：

```json
{
  "duck_count": 10,
  "duck_levels": [4,4,2,2,5,5,1,1,1,1],
  "duck_states": ["idle","idle","breeding",...],
  "corn": 12410,
  "stars": 150,
  "egg_board": {"capacity": 25, "occupied": 6, "max_level": 8},
  "market": {"my_listings": 1},
  "queue": 0
}
```

**校验方式**：连续 3 次读取一致，且与基线文件逐字段相等；任一字段不一致 → 该次实验作废，
记 `init_mismatch`，不计入成功率分母。

### 5.3 随机因素

| 来源 | 处理 |
|---|---|
| 蛋队列自动补货 | 记录 `queue` 初值与补货次数，作为协变量；不消除 |
| 游戏内限时活动 | 活动期间**暂停实验**（记 `env_blocked`） |
| 网络/客户端卡顿 | 单次任务超时上限内允许 1 次 `recovery`，超过即判失败 |

## 6. 观察策略（本实验的自变量）

**一次观察** = 抓一帧 + 抽取一次状态（不是"看一眼"的修辞）。

| 策略 | 定义 | 触发条件 |
|---|---|---|
| **低频（f_low）** | 每完成一个**动作序列**（≤5 个动作）观察 1 次 | 动作计数 |
| **事件触发（f_evt）** | 动作后若检测到界面变化则观察 | 帧差 > 阈值 |
| **高频（f_high）** | 每个动作后都观察 | 每动作 |

计量：`observations_per_task = 观察次数 / 任务次数`，并同时记录 `actions_per_task`。

> 若策略实现允许"看起来不观察也能拿到状态"，必须在记录里区分
> `observed`（真实抓帧）与 `assumed`（沿用上次状态），否则频率这个自变量是假的。

## 7. 动作空间（固定）

| 动作 | 参数 | 说明 |
|---|---|---|
| `click(x, y)` | 归一化坐标 | 主操作 |
| `drag(x1,y1,x2,y2)` | 归一化坐标 | 滚动/拖拽 |
| `wait(t)` | 秒 | 显式等待 |
| `observe()` | — | 显式抓帧（计入观察次数） |
| `abort()` | 原因 | 主动放弃（计入失败） |

禁止：多步宏、隐藏的自动重试。**重试必须显式记为动作**，否则"无效动作率"会被低估。

## 8. 状态读取与可信度（本协议的前置条件）

> 教训来源：本项目的玉米读数在同一时刻被读成过 51 / 6189 / 7276。**测量不可信 = 实验无效。**

每个被测字段必须满足：

1. **提取方法写明**（OCR / 模板 / 颜色阈值 / 结构解析）；
2. **稳定性测试**：连续 3 次读取一致才采信，不一致重读；连续 3 轮不一致 → 该字段标记 `unreliable`；
3. **交叉验证**：关键量（玉米、鸭子数、蛋等级）用两条独立方法各读一次，不一致则不计分；
4. **误差率登记**：每个字段在 200 次抽样上的错误率写入 `results/duck_bench/readers.json`；
5. **不可信字段不得参与判分**。宁可换任务，不许放宽判据。

## 9. 指标与统计

### 9.1 主指标

| 指标 | 定义 |
|---|---|
| 成功率 | 通过次数 / 有效次数（作废样本不计入分母） |
| 完成时间 | 首个动作 → 终局判据成立（秒） |
| **每任务观察次数** | 观察次数 / 任务数（本实验核心协变量） |
| 无效动作率 | 无状态变化且非 `wait` 的动作 / 总动作 |
| 恢复次数 | `recovery` 事件数 / 任务 |
| 失败类型分布 | 见 §10 |

### 9.2 统计口径

- 每组 **n ≥ 20**，报告 **均值 + 95% 置信区间**（bootstrap，1000 次重采样）；
- 组间比较用 **Welch t / Mann-Whitney**（不假设等方差）；比例用 **Fisher 精确检验**；
- 多重比较（A/B/C/D 六对）用 Holm 校正；
- **必须报告效应量**（Cliff's δ 或 Cohen's d），只报 p 值不算结论。

## 10. 失败分类（互斥）

| 类型 | 判据 |
|---|---|
| `timeout` | 达到任务超时上限 |
| `init_mismatch` | 初始状态与基线不一致（样本作废） |
| `state_unreliable` | 终局判据所需字段被标记 `unreliable` |
| `task_incomplete` | 状态可读但未达终局判据 |
| `env_blocked` | 弹窗/活动/断网等外部原因 |
| `policy_error` | 策略执行出错（异常、死循环） |
| `aborted` | 策略主动 `abort()` |

## 12. 门禁（硬约束，违反即实验作废）

1. **没有自动化终局判据** → 不得开始正式实验；
2. **初始状态不可复现**（§5.2 校验失败）→ 不得比较实验组；
3. **评分程序没有独立测试** → 不得发布结果；
4. **只报告成功案例** → 不得宣称实验通过；
5. **没有对照组** → 不得声称验证了 H1；
6. **不可采信字段参与判分** → 结果作废；
7. **C/D 组在策略接口与模型就绪前开跑** → 结果作废。

不设"人工标注/人工审核"作为验收门禁。Ground truth 一律来自**游戏环境可读取的真实状态**。

### 14.3 五个方面专项结论

| 方面 | 结论 | 证据 |
|---|---|---|
| **状态读取** | ⚠️ **部分可用** | 蛋板可（标注核对过）；玉米/星星**不可**（51/6189/7276 同刻不同值）；鸭子数量**不可**（9/10/11）；市场挂单数**读不到**（市场页只有"我的市场"标签，无计数） |
| **观察机制** | ❌ **不可独立控制** | `_stable_icons(tries=8)`（L1341）、`read_price(tries=3)`（L2252）、`read_feed_state(tries=3)`（L2299）、`duck_slots_from_inventory` 的 **30 分钟缓存**（L2008/L2014）、`do_feed` 批内 8 击不观察（L2383）。全项目**没有** `observed` / `assumed` 的区分 |
| **动作执行** | ❌ **不可追溯** | `click_slot_verified` 内置 `tries=2` + ±0.014 微调（L1137）；`_step_duck` 内含 `for k in range(2)` + 导航兜底；`do_merge` 内置 blocked 重试。**没有逐动作事件**，无效动作率无法计算 |
| **终局判定** | ❌ **无独立来源** | `status.json` 与 `events.jsonl` 都由执行器自己写；`duck_report.py` 只是对自报数据做二次加工。**不存在**独立的只读读取器 |
| **可重复性** | ❌ **不可复位** | 全项目无 reset/init；鸭子、蛋板、玉米都是玩家进度，脚本无法恢复；无 `run_id`，无 per-run 记录 schema |

### 14.4 建立可信 Bench 所需的最小代码集合

只保留 7 项（其余全部不进）：

1. `Game` + `find_game_window` + `ui_icons.grab`（窗口/坐标/点击/取帧）
2. `detect_board_cells` / `board_capacity`（蛋板状态，已核对）
3. `read_duck_profile`（卡片字段，**须先过 §8 认证**）
4. **动作原语**：`click / drag / wait`（从 `do_feed`、`do_merge` 里抽出，**禁止内部重试**）
5. **`observe()`**：显式抓帧 + 状态抽取（替换所有隐式读取与缓存）
6. **独立只读读取器**（新写：另一个进程，只读游戏画面，不持有执行权）
7. **run 记录器**（新写：按 §11 schema 落 `results/duck_bench/`）

明确**不进**最小集合：调度（`tiers_due`/`one_cycle`）、面板、领奖/广告/敲蛋/解锁、`exp_loop`、`duck_report.py`。

### 14.5 阻断项（不解决则 P2 无法启动）

| 编号 | 阻断项 | 影响的门禁 | 说明 |
|---|---|---|---|
| **B1** | 无独立只读读取器 | §12.3「评分程序必须有独立数据来源」 | 现状只能读到执行器的自报 |
| **B2** | 无初始化/复位能力 | §12.2「初始状态不可复现不得比较实验组」 | 游戏状态不可恢复 → 需在 P2 明确降级为**准实验**（记录初值并分层），否则实验不成立 |
| **B3** | 观察频率不可控 | §6 自变量定义 | 内置重试 + 缓存 + 批动作，使"观察次数"不可计量 |
| **B4** | 隐藏重试与隐式动作 | §7 §9.1「无效动作率」 | 动作数不可精确计数 |
| **B5** | 关键字段未认证 | §8 §12.6 | 玉米、鸭子数无误差率登记 |
| **B6** | 无 `run_id` 与 per-run schema | §11 | 无法回放与配对分析 |

**B2 已裁定（2026-11-17）**：选 (b)。DUCK 不承担 A/B/C/D 因果对照，
只做真实环境外部效度检验，因此**不再要求解决复位问题**，作为环境限制正式记录在案。

### 14.6 阻断项定级（裁定后）

| 编号 | 定级 | 说明 |
|---|---|---|
| B1 无独立只读读取器 | **必要** | 外部效度测试同样需要独立判分，否则测的是执行器自报 |
| B3 观察频率不可控 | **必要** | DUCK 上要研究"观察策略效果"，自变量必须先可计量 |
| B4 隐藏重试/隐式动作 | **必要** | 否则无效动作率与动作数不可比 |
| B5 关键字段未认证 | **必要** | 玉米、鸭子数必须先有误差率登记 |
| B6 无 run_id / per-run schema | **必要** | 准实验靠配对与分层，没有逐次记录就无法分析 |
| ~~B2 无复位能力~~ | **不要求** | 环境限制；因果验证已移交合成 GUI |

## 15. 风险与已知局限

| 风险 | 影响 | 缓解 |
|---|---|---|
| **模型规模这一维目前不存在** | C/D 组无法开跑 | 四组统一放合成 GUI；DUCK 只做外部效度 |
| **DUCK 状态不可复位** | 配对实验不成立 | 已裁定：因果验证移交合成 GUI，DUCK 仅做准实验 |
| 游戏是黑盒，状态只能从像素读 | 判据不可靠 → 实验无效 | §8 三重校验 + 不可信字段剔除 |
| 环境非确定性（补货、活动、卡顿） | 组间不可比 | 交错执行 + 协变量记录 + `env_blocked` 剔除 |
| 规则策略可能"作弊式"利用 UI | 动作空间被绕过 | §7 禁止隐藏重试；`observe()` 显式计量 |
| 样本量小（n=20） | 置信区间宽 | 只宣称大效应；小效应标"未决" |
