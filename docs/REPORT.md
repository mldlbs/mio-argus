# MioArgus 技术报告

> 汇总报告。所有数字来自本项目实测，可复现脚本与 commit 见 §9。
> 每条主张标注证据等级；**负面结果与自我修正一并列出，不做修饰。**

---

## 摘要

MioArgus 的目标是回答一个问题：**能否用一个小模型，在 Computer Use 这个窄域里
达到接近大模型的有效表现？**

我们没有训练更大的模型，而是把问题拆成四个可独立证伪的机制假设
（H1 重观察替代参数、H2 动作空间压缩、H3 验证替代精度、H4 窄域低熵），
在一个自建的合成 GUI 环境上逐个测量，并额外检验了一条“population 自进化”路线。

**结果：H1、H2、H4 成立；H3 分裂为对立的两半（重新接地 ❌ / 结果验证 ✅）；
population 路线无能力证据。**

四个独立实验最终收敛到同一个结论：

> **CUA 的瓶颈是“必须从高熵输入里恢复哪些信息”，而不是“模型有多大”。**

全部实验在单张消费级 GPU 上完成，模型规模 4K–1.5M 参数，**未使用任何外部 API**。

---

## 1. 问题与约束

| 约束 | 含义 |
|------|------|
| 数据少 | 没有海量 UI 截图，人工标注长轨迹极贵 |
| 不想堆参数 | 目标是“小而强”，不是“更大” |
| 要求方法创新 | 拒绝“更多截图 → 更大模型”的线性路线 |

**核心判断**：CUA 与通用视觉不同，它有几条可利用的结构性性质：
屏幕是外部记忆、可操作元素离散且稀缺、任务是程序性知识、结果往往可机械判定。

四条假设就是把这四条性质变成可测量的命题。

---

## 2. 实验平台

所有实验共用一套自建环境（`p0_env.py` / `p1_horizon.py` / `p3_env.py`）：

- **合成 GUI**：grid×grid 的元素阵列，每个元素有 label / bbox / role / color
- **两种等价接口**：像素 `(x,y)` 与元素 `slot`，判据统一为“执行点是否落在目标 bbox 内”
- **确定性**：全部可种子复现
- **难度坐标**（P0/P1 实测得出，是所有 curriculum 的基础）：

| 轴 | 参数 | 实测效应 |
|----|------|----------|
| 精度要求 | 元素尺寸 `fill` | 0.75→0.28 使回归从 1.00 掉到 0.38 |
| 步长 | `H` | π 从 0.98（H=1）掉到 0.80（H=8） |
| 环境变化率 | `ρ` | ρ=1 时开环直接归零 |

**一条贯穿全项目的实现纪律**：**几何与状态必须分离**。
元素 jitter 只能由固定的 `geom_seed` 决定，否则帧间所有元素位置都在变，
真正的状态信号会被渲染噪声淹没（P1 与 P3 各踩过一次）。

## 3. H2 — 动作空间压缩 ✅

**假设**：在元素集合上做**选择**，比在像素空间**回归**便宜一个量级。

**设计**：同一观测、同一 backbone、**参数量完全相同**，唯一变量是动作参数化。

```
reg : heatmap → soft-argmax → (x, y)      连续空间
cls : heatmap → g×g 池化   → slot          离散空间，熵 = log S
```

### 结果

**难度轴 A：精度要求（grid=6 固定，元素尺寸递减）**

| fill | precision | cls | reg | Δ |
|------|-----------|-----|-----|---|
| 0.75 | 0.125 | 1.0000 | 0.9970 | +0.003 |
| 0.55 | 0.092 | 0.9995 | 0.8085 | +0.191 |
| 0.40 | 0.067 | 1.0000 | 0.5110 | +0.489 |
| 0.28 | 0.047 | 1.0000 | 0.3785 | **+0.622** |

**难度轴 B：元素数量（fill=0.40）**

| slots | cls | reg | Δ |
|-------|-----|-----|---|
| 9 | 1.0000 | 1.0000 | +0.000 |
| 25 | 1.0000 | 0.5025 | +0.498 |
| 64 | 1.0000 | 0.0480 | **+0.952** |

**参数量（64 元素）**：12K 参数的 cls ≈ 99.8%，392K 参数的 reg 仅 5.5–10.6%。
**32 倍参数换不回性能。**

**关键诊断**：reg 的 `cell_acc` 通常仍在 0.95–1.00，说明它**找到了位置却不够准**；
只有在 64 元素时 cell_acc 才崩到 0.30，粗定位也开始失效。

### P0.5：把 oracle 结构换成廉价解析器 ✅

P0 的结构化接口用了 oracle bbox。换成**不含任何学习模型**的经典 CV 解析器
（阈值 + 形态学开运算 + 连通域）后扫描解析器质量：

| 档位 | recall | IoU | parser-cls | reg | Δ |
|------|--------|-----|-----------|-----|---|
| clean | 1.000 | 0.717 | 1.0000 | 0.4935 | +0.507 |
| jit2 | 1.000 | 0.499 | 0.9995 | 0.4935 | +0.506 |
| drop15 | 0.854 | 0.431 | 0.8535 | 0.4935 | +0.360 |
| drop30 | 0.700 | 0.355 | 0.6985 | 0.4935 | +0.205 |
| heavy | 0.498 | 0.163 | 0.4720 | 0.4935 | **−0.022** |

三条结论：
1. `cls_hit ≈ parser recall` —— 瓶颈是**召回**，不是选择能力
2. **抖动几乎无害**：IoU 从 0.72 掉到 0.50，cls 仍 99.95%
3. **crossing 在 recall ≈ 0.5**，给出具体工程目标：**目标元素解析召回 > 0.5**，
   框精度要求宽松得多

### P7：迁移到真实自由布局 UI —— ⚠️ **条件成立**（本项目最重要的限定）

去掉网格（元素自由摆放、大小不一、圆角/阴影/渐变、纹理背景），
做**两因子分解**，把"动作空间优势"与"解析器代价"分开：

| config | recall | reg | cls-oracle | cls-parser | space | parser cost | cls-parser vs reg |
|--------|--------|-----|-----------|-----------|-------|-------------|-------------------|
| sparse+flat | 0.905 | 1.0000 | 1.0000 | 0.8967 | +0.000 | +0.103 | −0.103 |
| extreme+flat | 0.845 | 0.9767 | 1.0000 | 0.8325 | +0.023 | +0.168 | −0.144 |
| **tiny+flat** | 0.847 | **0.7125** | 0.9992 | **0.8392** | +0.287 | +0.160 | **+0.127** |
| **micro+flat** | 0.725 | **0.4967** | 0.9875 | **0.7192** | +0.491 | +0.268 | **+0.223** |
| tiny+texture | **0.026** | 0.6375 | 0.9975 | 0.0117 | +0.360 | +0.986 | **−0.626** |
| tiny+natural | **0.077** | 0.6058 | 0.9950 | 0.0558 | +0.389 | +0.939 | **−0.550** |

**三条发现：**

1. **动作空间优势随精度要求增长，在自由布局上同样成立**：
   元素从 ~31%（sparse）缩到 ~7%（micro）时，space 效应从 +0.000 升到 **+0.491**
   ——与 P0 在网格上的规律一致。
2. **crossing 出现**：在 `tiny`/`micro`（元素 ~7–9%）上 `reg` 崩到 0.71/0.50，
   **`cls-parser` 反超**（+0.127 / +0.223）。这是机制在真实风格 UI 上的首次验证。
3. **解析器在非均匀背景上崩溃**：recall 从 0.847（flat）掉到 **0.026（texture）**，
   于是即使精度要求很高，`cls-parser` 仍大输（−0.55 ~ −0.63）。

**统一成一条不等式（12/12 全部符合，含 P0.5）：**

> **`cls-parser` 优于 `reg`  ⟺  `parser_recall > reg_accuracy`**

P0.5 当年看到的 "crossing 在 recall ≈ 0.5" 不是巧合——
那只是因为当时 `reg = 0.4935`，交叉点恰好落在 0.5 附近。

**⇒ 结构化动作空间的实用区间 = `{精度要求高} ∩ {解析器可靠}`。**
真实桌面 UI 里，**小图标 + 干净背景**（工具栏、图标网格）落在区间内；
**纹理背景 / 照片 / 画布类应用**不在其中。

**这不是对 H2 的否定**（机制在受控条件下 12/12 验证，且在自由布局上也复现了），
而是把它落成一个**可计算的不等式**：瓶颈是解析器召回与回归精度的比较。
"把结构从像素里恢复出来"这一步的成本，正是"小而强"假设最脆弱的地方。

### P8：学习式检测器 —— "参数搬家"风险被证实

P0.5 埋过一个风险：**"如果解析器本身要个大模型，那就只是把参数搬了个位置。"**

P8 用一个可缩放的学习式检测器（CenterNet-lite）替换朴素 CV 解析器，
在 `tiny` 布局（42 个 8–26px 元素）上测判据 `total_params < reg_params` 且 `cls > reg`：

| 解析器 | flat recall | texture recall | 参数 |
|--------|------------|----------------|------|
| **经典 CV（人工先验）** | **0.847** | 0.026 | 0 |
| **学习式检测器** | 0.518 | **0.456** | 24K–94K |

**要求是 `recall > reg_acc`**（flat 需 > 0.784，texture 需 > 0.623）：

- 学习式检测器 **recall 在 ~0.52 处饱和**——容量从 24K 到 94K、
  训练从 22 到 60 epochs，几乎无改善
- **12/12 配置 `cls < reg`**
- 更反直觉：**干净背景上零参数的人工先验远胜学习**（0.847 vs 0.518）

**⇒ P0.5 的警告被证实为否定性的**：小预算下解析器达不到门槛，
而且瓶颈不在容量，而在**检测任务本身比回归任务难**。

**重要补充**：真实世界里 **a11y / DOM 树会推翻这个结论**——
桌面与 Web 应用大多直接暴露结构化树，解析器接近免费且近满召回，
条件立刻满足。**但那时问题已经不是视觉问题了。**

**⇒ 结构化动作空间的实用区间最终定格：**

```
{精度要求高} ∩ {解析器可靠}
```

- **a11y / DOM 可用**（多数桌面与 Web 应用）→ 在区间内，且无需视觉解析
- **只能看像素**（游戏、远程桌面、画布、图像类）→ **不在区间内**

见 [results/paper/P8_RESULTS.md](..\results\paper\P8_RESULTS.md)。

## 4. H1 — 重观察替代参数 ✅

**假设**：重新观察可以替代参数化世界知识，且这个替代价值随 horizon 增长。

**设计**：H 步任务，布局每步以概率 ρ 重随机，观察间隔 k（`k=1` 闭环，`k=H` 开环）。

### Sanity check

ρ=0（静态布局）时，`k=1/2/4/8` 结果**逐位相同**。
证明无渲染伪影，且**环境不变时重观察价值为零**——这是假设成立的边界条件。

### 结果

**ρ=1（每步都变）**

| H | k=1 | k=2 | k=8 |
|---|-----|-----|-----|
| 1 | 1.0000 | — | — |
| 2 | 0.9933 | 0.0133 | — |
| 4 | 0.9967 | 0.0000 | 0.0000 |
| 8 | **0.9967** | 0.0000 | 0.0000 |

**重观察的价值随 H 单调增长**（`gap = succ(k=1) − succ(k=H)`，ρ=0.3）：

| H | k=1 | k=H | gap |
|---|-----|-----|-----|
| 1 | 1.0000 | 1.0000 | +0.0000 |
| 2 | 1.0000 | 0.7133 | +0.2867 |
| 4 | 0.9967 | 0.3433 | +0.6534 |
| 8 | 1.0000 | 0.0767 | **+0.9233** |

### 两个机制被干净分离

| 机制 | 证据 |
|------|------|
| **H1 重观察** | ρ=1, H=8：k=1 → 0.9967，k=8 → 0.0000 |
| **H2 动作结构** | k=1, H=8：cls **0.9900** vs reg **0.0067** |

关键：**reg 的崩塌与 k 无关**（ρ=0 时各 k 完全相同），它是**误差复利** p^H
（每步 0.51 → H=8 时 0.007），不是观察缺失。**两类失败必须分开归因。**

## 5. H3 — 验证替代精度 ⚠️（拆成对立的两半）

**原假设**：一个远小于策略的 verifier 能 gate 策略，组合系统优于等算力单体。

### 形式 A：重新接地的 verifier ❌ 证伪

若 V 必须重新接地来判断候选动作对不对，则

```
π 的 logit(c) = 在格 c 区域对 <q, feat(p)> 取平均 = <q, f_c>
V 的 score(c) = <q, 在格 c 区域对 feat(p) 取平均> = <q, f_c>   ← 恒等
```

**RoI-pool 与点积可交换**（实测：共享权重时分数最大绝对差 0.007153）。
验证与选择是**同构问题**，`(π,V)` 不可能超过 `π`。

实证：策略欠训练时 V 使成功率 0.86→0.60；策略收敛后双双饱和无空间。

**⇒ H3 不能作为与 H2 独立的第二个收益来源。**

### 形式 B：结果验证 ✅ 成立

H3 唯一还活着的形式是检查**动作的结果**：

```
V(旧屏幕, 新屏幕) → 进度是否推进？
```

这需要环境暴露**可观察的进度信号**。P3 构造了这样的环境：
顶部进度条只在正确动作时推进；错误动作留下红框但进度不动。
所以“屏幕变了” ≠ “进度推进了”。

**结果**（π = 106,112 参数；V = **6,393 参数，小 17×**，acc = 1.0000）：

| ρ | H | π | π + V | V 增益 |
|---|---|-----|-------|--------|
| 0.3 | 1 | 0.9800 | 0.9900 | +0.0100 |
| 0.3 | 4 | 0.8367 | 0.9000 | +0.0633 |
| 0.3 | 8 | 0.5567 | 0.7033 | **+0.1467** |
| 1.0 | 1 | 0.9767 | 0.9967 | +0.0200 |
| 1.0 | 4 | 0.8367 | 0.9733 | +0.1367 |
| 1.0 | 8 | 0.8033 | 0.9467 | **+0.1433** |

**增益随 H 单调上升，且 `π+V = π+oracle`（已达上界）。**

### H3 的精确边界

| verifier 类型 | 结论 | 原因 |
|---------------|------|------|
| 重新接地 `V(c)` | ❌ | 与 π 同构 |
| 结果验证 `V(旧,新)` | ✅ | 用了 π 没有的信息：动作的**后果** |

> **H3 的本质不是“验证比选择简单”，而是“验证能否用到策略拿不到的信息”。**

### P6：验证器需要多准？（补上"无噪声"这个局限）

给 V 注入可控错误率，区分子类：**FNR**（误拒正确动作）与 **FPR**（误收错误动作）。

**两条结论：**

1. **FNR 与 FPR 的代价极不对称**（ε=0.40, H=8）：
   FNR → **0.0450**，FPR → **0.8750**。
   FNR 会摧毁本来确定的成功；FPR 只是没能挽救本来就要失败的步。
   ⇒ **闭环 verifier 必须校准到偏向"接受"**（宁可放过，不可错杀）。

2. **容错随 horizon 收紧，近似 `ε* ≈ 0.8 / H`**：

   | H | 2 | 4 | 8 |
   |---|---|---|---|
   | 半衰 ε | 0.40 | 0.20 | 0.10 |

   H 每翻一倍，容错减半——与 H1 的误差复利机制一致。
   **工程目标**：H=8 的任务要求 verifier FNR < 10%。

详见 [results/paper/P6_RESULTS.md](..\results\paper\P6_RESULTS.md)。

## 6. H4 — 窄域低熵 ✅（机制被修正）

**假设**：UI 输入的熵远低于自然图像，所以达到同等能力所需参数更少。

**设计**：同任务、同输出空间、同元素与网格渲染，**只改背景熵**。
这样把“输入熵”从“任务难度”里分离出来。

| 级别 | w4（4,208 参数） | w32（99,968 参数） |
|------|-----------------|-------------------|
| **E0 纯色** | **0.9380** | **0.9980** |
| E1 逐像素噪声 | 0.7430 | 0.5390 |
| E2 低频色块 | 0.1270 | 0.6150 |
| E3 自然图像裁剪 | 0.6770 | 0.8890 |

达到 0.80 所需参数：**E0 ≤ 4,208** / E1 = 5,053 / E2 从未达到 / E3 = 8,845。

**H4 方向成立**：低熵输入用 4,208 参数就达 0.938 并饱和；
自然背景要 8,845 参数才到 0.80，100K 参数仍只有 0.889。

### 但机制不是“熵”

| | E1 逐像素噪声 | E2 低频色块 |
|---|---|---|
| 像素熵 | **最高** | 较低 |
| 最好成绩 | **0.872** | 0.615 |

逐像素 i.i.d. 噪声被卷积**平均掉**，几乎无害；低频色块产生大块连贯区域，
**伪装成元素，制造假阳性**。这才是吃掉容量的东西。

> **修正后的 H4**：成本来自“存在与目标同类、需要被区分的**结构化干扰**”，
> 不是像素熵本身。UI 省参数的本质是**可操作元素稀缺且离散**。

可量化的新指标（待做）：**干扰项与目标在特征空间上的重叠度**。

## 7. population 自进化 ❌（方法学上被污染）

这条路线是后加的：小模型 + 多模型竞争 + 自动生成数据 + 环境验证 + 递归进化。

### 演进与自我否定

| 实验 | 表面结论 | 实际结论 |
|------|----------|----------|
| **P4a** | 专精存在（错误集 Jaccard ≈ 0）但 coverage 增益 ≈ 0 | 通才在 1/5 参数预算下已饱和 → population 无价值 |
| **P4a'** | 加宽任务空间（6 个 domain 各自的颜色置换）后 population 109K 参数 → 0.6887 vs 通才 100K → 0.3273，**+0.361** | 看似成立 |
| **P4c-OOD** | 留出未见 domain 后优势从 +0.4025 掉到 +0.0158 | **是记忆效应，不可迁移** |
| **P4d** | 通才扫到 1.5M 参数（14×）仍追不上 | 原因是**域不可识别**，不是容量 |

### 最终裁决

P4d 暴露了根因：**通才只看到（屏幕, 指令），无法推断当前是哪个 domain**
（domain 只体现在 label→color 映射上，而模型不读文字）。
这个任务对它在**信息上就不可解**——屯多少参数都补不上缺失的输入。

**这 retroactively 否定了 P4a'**：它测的不是“专精 vs 泛化”，
而是“**有域信息 vs 无域信息**”——专精者因只训练一个域而**隐式获得了域身份**。

> **P4（population self-evolution）没有建立起任何能力层面的主张。**
> 唯一站得住的是“互不相关子域 + 单一策略无法覆盖时，MoE + 路由器优于等参数单体”
> ——这是已知结论，**不构成研究贡献**。

补救尝试（P4e：把 domain 做成屏幕可观察）**未完成**：实现时遇到渲染不一致，
标定后专精者仍远低于基线（0.31 vs 0.75），无法判定是渲染 bug 还是任务变化。
脚本已移除，缺口记录在 [results/paper/P4D_RESULTS.md](..\results\paper\P4D_RESULTS.md)。

## 8. 收敛结论

四条独立实验线指向同一个点：

| 线 | 结论 |
|----|------|
| **H2** 动作空间压缩 | **动作**离散化省参数 |
| **H3** 结果验证 | 验证的价值取决于能否拿到策略看不到的信息 |
| **H4** 输入干扰 | 成本来自**结构化干扰**，不是像素熵 |
| **P4d** 域不可识别 | 信息不在输入里 → 加参数无用 |

> ### CUA 的瓶颈是“必须从高熵输入里恢复哪些信息”，而不是“模型有多大”。

这是整个项目**唯一一个从四个独立实验里长出来**的结论。
它也解释了为什么“小而强”在这个域里**可能**成立：
不是小模型更聪明，而是 CUA 把一部分信息搬到了环境里，
而**搬走的那部分恰好是参数需求的大头**。

### 但 P7 把这条结论落成了一个可计算的不等式

P7 把环境推到自由布局 + 纹理背景后，把"结构化是否划算"化简为两个数的比较：

> **`cls-parser` 优于 `reg`  ⟺  `parser_recall > reg_accuracy`**

（12/12 配置符合，含 P0.5。）

所以更精确的表述是：

> CUA 的瓶颈是**能否廉价、可靠地把结构从高熵输入里恢复出来**。
> 这个"恢复"步骤的成本（解析器召回）与回归基线的精度之间的比较，
> 决定了结构化小模型是否真的划算。

**结构性动作空间在 `tiny`/`micro`（元素 ~7–9%）+ 干净背景上确实反超了坐标回归**
（+0.127 / +0.223），但在纹理/自然背景上解析器崩溃，优势全失。
**这就是"小而强"假设的真实边界。**

**QGIS 线最终留下的四条结论**（取代早期的"H1/H3 已有真值证据"的粗结论）：

1. **通道的真实账**（W13–W15）：UIA 工具栏覆盖 61%→（+菜单）89%，动作成本
   特权 50 ms / 工具栏 140 ms / 菜单 720 ms / **快捷键 101 ms（须 OCR 发现）**；
   **真约束是可访问性覆盖，不是"像素 vs 结构"**——修正 rect 后 pixel 与 struct 同分。
2. **H1 的"静默错误"形式**（W4/W16/W19）：过期坐标点中隔壁按钮、对话框字段状态跨调用持久化、
   未聚焦窗口的第一下鼠标点击被"激活窗口"吃掉——三者都是**动作发出但没发生/发生错**，
   必须用结果验证兜底（按钮优先 UIA `Invoke`）。
3. **V 的价值是条件式的**（W9–W12）：依赖式子目标把它从 0 变成正，但真 actor 的错误是
   **系统性**的，重掷不独立 ⇒ V 只对"弱策略 + 随机错误"划算（吞吐分水岭 q\*≈0.53）。
4. **真工作流可跑通但贵且脆**（W16–W19）：零特权调用的"选择 + 导出"工作流 **4/4、~18.9 s**
   （同产物走 PyQGIS 31 ms ⇒ **~600×**）；GUI 的低层不可靠性（句柄过期、子菜单不可见、
   焦点吃点击）需要显式的重取/验证/Invoke 才能压住。

## 9. 方法学上的自我修正（全部保留）

项目过程中被发现并修正的缺陷，**逐条列出**：

| # | 缺陷 | 后果 | 修正 |
|---|------|------|------|
| 1 | P0 缓存 key 未包含 `fill` | 所有尺寸配置复用同一份数据，扫描 A 形同虚设 | key 覆盖全部 env 参数 |
| 2 | `gauss` 热力图监督实现偏弱 | 被当作 reg 基线，**高估 Δ**（grid=6 报 0.07，强基线实为 0.50） | reg 统一用 coord 损失 |
| 3 | P1 同一布局重复渲染导致 jitter 变化 | ρ=0 时 k 仍有影响，伪影 | 布局未变则复用同一帧 |
| 4 | P1 跨 k 使用了不同 seed | 不同观察间隔跑的不是同一批任务 | seed 与 k 解耦 |
| 5 | P3 成功判据误用“verifier 接受” | 恒说接受的 V 能刷满任务 | 判据改为 `progress` 真的推进 |
| 6 | P3 指标命名错误（把 FPR 写成 TNR） | 误判 V 已崩溃 | 修正指标定义 |
| 7 | P4a' 信息不对称未被察觉 | 把“有域信息 vs 无域信息”当成“专精 vs 泛化” | 由 P4c/P4d 暴露并撤回 |
| 8 | P4e 渲染不一致 | 补救实验无法判定 | 停止并如实记录，脚本移除 |
| 9 | `OutcomeVerifier` logit 尺度漂移 | 固定 0.5 阈值导致偶发"恒输出正类"崩溃（3 次运行中 1 次） | 验证集阈值校准 + 低 AUC 重试 |
| 10 | 阈值搜索用均匀网格 | 漏掉尺度漂移后的最优点，一度误判为"模型没学到" | 改为排序分数相邻中点（精确） |
| 11 | P6 噪声翻转共用 rng | 不同 ε 跑的任务不同，不可比 | 噪声用独立 rng |
| 12 | W9 的 V 实际读到的是"无匹配要素"**警告弹窗**，不是选择状态 | 正例 after≈before（diff=0.0001），AUC 0.968 是伪迹 | 换成**可观测结果**（多边形）+ 无弹窗错误变体 → AUC 1.000（W10） |
| 13 | W10/W11 的 V 增益建立在"硬币 actor"（均匀随机错误）上 | 增益 +0.583→+0.833 不可外推 | W12 换真 actor：V 收益消失甚至变负（系统性错误重掷不独立） |
| 14 | 桥的动作 rect 与真实按钮位置不符（名字对、位置错，差 145–277 px） | W6/W7/W12 的 pixel 臂是在**错位裁剪**上评测的 | W13 换 Windows UIA（名字+rect 双验证）重测：pixel 未见状态 **1.000** |
| 15 | 真值规则"更接近正确参照"被随机预置状态骗 | "Zoom Full" 标签 79% 假正例，V 学成 AUC 0.37 | 改为"容差 + 最近参照"双条件（W10/W12） |
| 16 | 对话框/算法参数会**跨调用记住上次状态**（保存对话框复选框、算法输入图层 id） | 静默产出错误产物（"导出全部"实际 2 个要素；Run 用旧 layer id 空转） | 每个字段显式设定并**读回校验**，不假定默认值（W16/W18） |
| 17 | W18 把偶发失败记为"可靠性 ~75%"，未根因 | 差点把它当成能力上限 | W19 加仪表：**未聚焦窗口的第一下鼠标点击被"激活窗口"吃掉** → 改用 UIA `Invoke` ⇒ 4/4 全首试 |

**其中 1、2、7、12、13、14 会直接改变结论方向**，9、16、17 会改变组件可用性，
都是通过额外的对照实验发现的，不是靠更仔细的审阅。

**第 9/10 条的方法论值得单列**：一个"偶发崩溃"组件的根因可能是
**判定阈值不可靠**，而不是**能力不足**。区分二者只用一个阈值无关量——**AUC**。
本项目里 AUC 恒为 1.0，而固定阈值的准确率在 0.49 与 1.00 之间摆动。

## 10. 局限

- **环境是合成的**，只有“点击”一种动作类型。**P7 已把环境推到自由布局 +
  圆角/阴影/渐变 + 纹理/自然背景**，并发现 **H2 在该条件下不成立**
  （`cls-parser` 输给坐标回归）。**WinSim（§8.5）把这条往前推了一步**：
  用一个可重放、有外部真值、可注入故障的桌面沙箱给出端到端数字
  （结构 1.00 / 像素端到端 0.79 / 混合 0.80），并复现了主题与应用的 OOD 掉幅。
  真实截图/真实站点仍未测——WinSim 是**受控中间层**，不是真实环境。
- **未测主假设的核心比较**：“小模型 vs 10¹⁰ 级大模型”。
  原因是本环境没有可用的 LLM API key。适配器已写好
  （`vlm_adapter.py`，支持 OpenAI / Anthropic，coord / mark 两种模式对应 H2 的两种接口），
  有 key 即可跑。
- H4 的“自然图像”来自 `assets/nanogpt.jpg` 的随机裁剪，不是真正的自然图像分布。
- H3 的 progress 信号是合成无噪声的。**P6 已补上"verifier 判断出错"的敏感性分析**
  （FNR < ~0.8/H；FNR 远比 FPR 有害），但仍未模拟"进度条本身误报/延迟/被遮挡"。
- 数值上存在训练随机性：`OutcomeVerifier` 曾出现偶发崩溃，根因是 logit 尺度漂移
  导致固定阈值失效。**已用验证集阈值校准修复（6/6 seed 到 100%）**，见

### 关于"主假设 vs 10¹⁰ 级大模型"：为什么它是低优先级

原假设字面上要求一个小模型打败 10¹⁰ 级模型。**但在本环境里做这个比较没有价值**：

1. **没有梯度**：小模型（4K–100K 参数）在合成 GUI 上已到 0.998，
   大模型最多 1.0——测出来是"双方饱和"。
   要制造梯度就得**专门设计一个假设会赢的任务**。
2. **会被一句话驳回**：在自己造的合成 grid 上"打败 GPT-4o"，
   是循环论证而非证据。
3. **会被彻底混淆**：小闭环模型赢大开环 VLM，到底赢在闭环（H1）、
   结构化动作（H2）、verifier（H3），还是 VLM 本来不擅长 GUI？
   **四种机制混在一个数字里什么也证明不了**——而我们已经把它们**单独测了**。
4. **API 模型不是可控基线**：训练数据未知、prompt 敏感、推理 FLOPs 测不准。

**若要做，唯一有价值的形式是"机制普遍性检验"而非"我们赢"**：

> 给大模型**同样的两种接口**（像素→坐标 / 元素列表→选择），
> 看 H2 的接口效应在它身上是否也成立。
> 成立 → H2 是**普遍原理**；不成立 → H2 只是小模型的拐杖。

这才是值得花 API 钱的地方，且答案开放。

## 13. 一句话总结

> 我们没有证明“小模型能打赢大模型”，我们**删掉了一半的问题**：
> 把参数从“记住世界”转移到“读环境 + 选动作 + 验结果”，
> 并逐个证明了这三个转移各自成立、边界在哪、以及一个看似有希望的
> 第四条路线（population）为什么其实是假象。
