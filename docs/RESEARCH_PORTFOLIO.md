# 研究组合与续行机制

> 本文回答一个流程问题，不是结果报告：
> **为什么每次证伪之后就停摆？怎么让研发持续下去？**
> 结论先行：**停摆不是因为证伪太多，而是因为把"测不出来"当成"被证伪"，且同一时刻只跑一条链。**

---

## 0. 一句话

现在的流程有三处结构性缺陷：

1. **三态混淆**——"被证伪 / 测不出来 / 主动放弃"被写成同一个结果，都触发关线；
2. **链式依赖**——每条新主张都建在上一条的结论上，所以否证一环 = 拆掉下一环的测量台；
3. **单一成功定义 + 人工关线**——只有最顶端那条主张算成功，且关线后要等裁定才有下一步。

结果：项目其实在**积累资产**（基准、门禁、分解方法、checkpoint），
但唯一的健康指标是"主张是否成立"，所以每一次终止都读作"项目失败"。

---

## 1. 诊断

### 1.1 最近 6 次终止里，4 次不是证伪

| 终止的线 | 类型 | 依据 |
|---|---|---|
| P9 主动缩放 | **FALSIFIED** | 12 格里 9 格 `random ≥ glimpse`，策略无效 |
| P4c-OOD | **FALSIFIED** | OOD 0.0583 ≈ chance 0.0278（seen 0.7208），优势不可迁移 |
| M1 难度轴 | **UNMEASURABLE** | 96 格 `H8/H1 = 0.02`（需 0.25），全地板，无窗口 |
| H4 干扰密度 | **UNMEASURABLE** | 主指标 `params_needed(0.80)` 两端截断 |
| E1-L 主实验 | **UNMEASURABLE** | 三档 `fill` 全饱和（`cls` 单步 1.000），无难度轴 |
| H-Crossing A2 | **UNMEASURABLE** | 臂单步坐标 0/84 → 2026-11-22 定位为**标签缺陷**（`COORD_HEAD_FINDINGS.md`） |

**这 4 次"不可测"被当成证伪处理，于是各自关了一条线、各花掉一轮"裁定"。**
但它们实际产出的是**仪器工单**（缺哪个量、用什么判据、改哪一行），不是主张的判决。

### 1.2 链式依赖：主张 n 的平台 = 主张 n−1 的结论

```
P0/P1 ─→ H3a/H3b ─→ H4 ─→ M1 ─→ M1b ─→ E1-L ─→ H-Crossing
   └─ 每一环的实验平台，都是上一环"成立"之后才存在的
```

否证 P4 → population 线没了；否证 M1 → E1-L 没窗口；H-Crossing 卡在 small 臂 →
**没有第二条可以直接接上的线**。所以每次终止都是项目级停摆。

### 1.3 成功只定义在链条顶端

"小模型靠闭环反超大模型"成立才算成功。于是：基准、门禁、误差分解、216 条冻结样本、
成本表——全部是**不可见的中间产物**。资产在涨，记分牌不动。

### 1.4 关线要人工裁定 → 决策延迟变成真瓶颈

预注册只锁了**判据**（"什么算通过"），没锁**响应**（"不通过时做什么"）。
所以每次 FAIL 都落在预注册之外，必须停下来问一次。V1（E1）有响应表，
但它只覆盖 E1 一条线，且是"假设成立/不成立"两条，不含"不可测"。

## 2. 机制一：三态终止（最重要的一条）

任何实验的终点只能是下面三个之一，**不许合并**：

| 状态 | 定义 | 允许的动作 |
|---|---|---|
| **FALSIFIED** | 仪器已证实（判据可达、覆盖窗口、臂合格），主张被数据否证 | 关闭该主张线；写边界；**不得**用"再调调参数"续命 |
| **UNMEASURABLE** | 仪器坏了：地板/天花板/截断/臂不合格/无能力 | **不得关闭主张线**；开仪器工单；线转"挂起（低耗）" |
| **ABANDONED** | 人力/算力/价值判断主动放弃 | 记录理由，不写"证伪" |

判定顺序固定：**先查仪器，再判主张**。顺序不能反——
反了就会出现"用 0/84 证明小模型不能定位"这种把管道 bug 写成能力结论的事。

**UNMEASURABLE 的三件套工单**（缺一件不算开单）：

1. 缺的是**哪个量**（例如：坐标掩码、难度窗口、成本计量）；
2. 用什么**判据**判定"仪器修好了"（最好是相对比较，不是拍阈值）；
3. 改**哪一行 / 跑几次**，以及这次改动是否触碰"需要批准"的红线（训练、花钱、发布）。

---

## 3. 机制二：臂门禁（A0）——先证仪器，再证主张

任何**比较型**实验，在 A1（资源/参数审计）之前必须先过 **A0**：

| # | 门禁项 | 问法 | 反例（本项目真实发生） |
|---|---|---|---|
| G1 | 能力地板 | 每个臂在靶标上的单步成功率是否 ≥ 一个已证可测的水平？ | H-Crossing small 臂坐标 0/84 |
| G2 | 非饱和 | 是否没有臂已经 1.000 / 0.000？ | E1-L：`cls` 三档全 1.000 |
| G3 | 非常数 | 输出是否随输入变化（`std(pred)/std(truth)` 不塌）？ | 坐标头 std 被压小 9× |
| G4 | 指标可达 | 主指标在预扫描里是否**覆盖到阈值区间**？ | H4 `params_needed` 两端截断 |
| G5 | 成本可分 | 理论 FLOPs / 时间 / 显存是否**分开**测得？ | 曾混用"参数量"当规模 |
| **G6** | **模态有效性** | 消融关键输入（图像/指令）是否真的改变输出？ | v3_real：换图只动坐标 0.0036，换指令动 0.117 → 图像被忽略 |

G1–G5 任一不过 → **不写预注册、不启动**。这条比"多跑一次"便宜两个数量级：
H-Crossing 的 A1（参数、成本）全过，A0 没过，结果 A2 才炸，代价是一整轮设计 + 审计。

## 4. 机制三：组合 + 预注册响应树（失败自动续行）

### 4.1 每条线的登记表（预注册的一部分）

| 字段 | 要求 |
|---|---|
| 主张 | 一句话，可证伪 |
| 检验 | 数据、判据、样本量、统计量 |
| KILL | 什么结果算 FALSIFIED |
| **若 PASS** | 已登记的下一步（不需要再裁定） |
| **若 FAIL** | 已登记的替代主张（不需要再裁定） |
| **若 UNMEASURABLE** | 仪器工单编号 + 同时启动哪条并行线 |

**关键改变：响应也是预注册的一部分。** 判据锁定只防"事后换尺"，响应锁定才防"停摆"。

### 4.2 什么才需要裁定

只有三类：

1. **新主张**（组合里没有的题）；
2. **改判据**（换指标、换阈值、换种子）；
3. **触碰红线**（启动训练、花钱、发布/推送）。

**续行不需要裁定。** 已有响应树的下一步，直接做。

### 4.3 组合作业规则

- **WIP ≥ 2**：任何时刻至少两条活跃线，且**至少一条不依赖任何模型能力**（仪器/方法类）；
- 一条线进入 FALSIFIED，当天从响应树取后继启动，不等复盘会；
- 一条线进入 UNMEASURABLE，当天开工单，线转挂起（低耗），**不占 WIP 名额**。

## 5. 机制四：关闭契约 + 资产账本

### 5.1 关闭契约（三件套，缺一不许标 closed）

| # | 交付物 | 判据 |
|---|---|---|
| 1 | **仪器** | 一个可复用的脚本/基准/门禁，别人能用来测别的主张 |
| 2 | **边界** | 被否证/不可测的量化数字（不是"效果不好"） |
| 3 | **后继** | 下一问句，且已进组合表 |

现在的关闭记录大多只有第 2 件（有时连第 1 件也没有），所以关线只减不增。

### 5.2 资产账本（第二健康指标）

| 资产 | 现状 | 覆盖 |
|---|---|---|
| 216 条冻结 GUI 基准 + 冻结评分器 | 已有 | UGround 0.491 / GUI-Actor 0.435 / 自研 grid 0.056 |
| 预扫描门禁 `prescan_gate.py` | 已有 | 阈值模式 + 区间模式 + 单调方向 |
| 误差分解（`I = S/∏m_t`） | 已有 | 三层次分离（观测/机制/裁定）预注册纪律 |
| 成本计量（FLOPs/时间/显存分列） | 部分 | 分辨率成本表 |
| 220M 动作分类器 | 已有 | 动作 84/84；坐标头待修 |

**规则：每条关闭的线必须留下 ≥1 个仪器。** 没有仪器的关闭，一律记为 ABANDONED，不算研究产出。

## 7. 节奏与度量

| 频率 | 动作 | 输出 |
|---|---|---|
| 每条线终止时 | 跑三态判定 → 取响应树 → 开工单/启动后继 | 3 行记录，不等裁定 |
| 每周 | 组合状态检查（活跃线、挂起线、工单） | 是否 WIP ≥ 2 |
| 每 4 周 | 资产 vs 主张对照 | 仪器数是否单调上升 |
| 每季度 | 至少一份可交付（**负结果也算**） | 边界 + 仪器 + 方法 |

**三个指标分开记，不合成一个分**：

1. **主张状态**：成立 / 否证 / 不可测 —— 会下降，正常；
2. **仪器覆盖**：能被复用的测量手段数 —— 应单调上升；
3. **可复现次数**：他人按文档能重跑出的次数 —— 应单调上升。

只看第 1 个，项目永远在死；只看第 2 个，会变成"造工具不自证"。**两个一起看。**

## 8. 明确不做

| 不做 | 原因 |
|---|---|
| 把 UNMEASURABLE 写成 FALSIFIED | 这是过去 6 次终止里 4 次的错误 |
| 用"再跑一次"修仪器缺陷 | 先改仪器（掩码/指标/窗口），再跑 |
| 仪器未过 A0 就启动正式训练 | 会得到一个不可解释的 checkpoint |
| 为让图表好看重写历史 | 已裁定（保留 upstream blame 与可 merge 性） |
| 扩 WIP 到"什么都开" | WIP 上限 3；超了就排队，不是并行失控 |
